首頁 ／ AI 輔助研究

實例：一個碩士生的 AI 研究流程

六個階段的實際做法、提示詞範本與 AI 犯過的錯

這頁是站主自己寫碩士論文時的實際做法：從找方向、查文獻、做筆記到送審前的審查，每個階段怎麼用 AI、可以拿去改的提示詞範本，還有 AI 在論文裡犯過的錯。原則面的整理在AI 輔助研究工作流，更多範本在AI 提示詞範本。

這份碩士論文是資管領域的橫斷面問卷研究，用 PLS-SEM 分析，從找方向到寫計畫書，大部分環節都有 AI 參與。下面的「通用」表示 ChatGPT、Gemini、Claude 網頁版都能照做；「進階」需要 Claude Code 或 Codex 這類 agent 工具。

一、六條原則

這六條是做完一輪回頭看，對品質幫助最大的做法。

  1. 範圍自己定，AI 負責找。 AI 不知道你的研究屬於哪個領域。只說「查資管期刊」，範圍就等於交給它決定。先想清楚要找哪一塊，再請它找。
  2. 先說出自己的想法。 不確定要什麼的時候，先請 AI 列選項或反過來訪談你，把想法講清楚再請它擬計畫。等它寫完才改，會一直被它的版本牽著走。
  3. 先規劃再執行。 把初步想法丟給 AI，請它把計畫寫完整，你看過再讓它做，有問題回頭問你。比一句一句下指令有效很多。
  4. 兩個工具互相檢查。 一個負責寫，另一個用沒看過前文的角度找漏洞。兩邊說法不一樣的地方，就是要回原文確認的地方。
  5. 數字和引用一律回原文。 AI 給的係數、引用、理論圖，都要對過 PDF 才能用。筆記寧可寫「查不到」，也不能寫錯。
  6. 提示詞和對話要存檔。 我整理 AI 使用揭露時才發現，前幾個月問了什麼大多記不得。從第一天就把重要決策的提問存下來。

二、工具分工

依使用頻率和重要程度排。每個工具負責什麼，要先分清楚。

工具 負責什麼
Claude Code 主要工具：改寫、核對文件、管理筆記與進度，和 Codex 分工
Codex 第二意見：扮成第一次看文件的委員找邏輯漏洞；和 Claude 各自查同一件事，再比對哪裡不一樣
Consensus、Elicit 學術搜尋。查詢問題由 Claude 先擬，我自己去搜，結果貼回去一起比對
ChatGPT 討論研究方向、找文獻；也用過網路上別人做的論文寫作 GPT
Perplexity 偶爾用來找文獻、想研究方向
NotebookLM 前期用過：文獻庫問答，查文獻之間的關係
Zotero ＋ Obsidian 不是 AI 工具，但筆記和引用都靠它們：Zotero 管 PDF 和書目，Obsidian 放筆記（見文獻管理與知識庫）

三、流程六階段

每個階段寫三件事：我怎麼做、提示詞範本、我踩過的坑。提示詞範本是我依這次的經驗整理、之後打算這樣問的寫法，不是當時的原文。

3.1 找方向與研究問題（通用）

我一開始的方向比較廣，請 AI 整理相關研究，看還有哪裡可以延伸，它給了一份完整的文獻回顧。我帶著模型圖和文獻去和指導教授討論，題目是在和老師的討論中定下來的。

我想研究［主題］，目前的想法是［一兩句話］。
請先不要給我題目，改用訪談的方式問我 5 個問題，
幫我釐清：這個研究比較屬於哪個領域（例如資管、教育科技、心理學）、
我真正好奇的現象是什麼、能用什麼方法回答。
問完之後，再列出 3 個可能的研究方向，每個寫出它屬於哪個領域、要讀哪類文獻。

我踩過的坑

AI 給的研究問題寫成「X 是否正向預測 Y？」，連我請 AI 幫忙整理的寫作指引也教這個格式。後來老師在課堂上說研究問題寫成是非題是大忌，我才全部改成「X 對 Y 的預測效果為何？」。AI 不知道你老師的規範，課堂上講過的寫法要自己對照。

3.2 查文獻（通用）

流程：AI 擬查詢問題 → 我到 Consensus、Elicit 搜尋 → 結果貼回去 → 和已有的文獻庫比對、排優先序。

查詢問題請 AI 擬，搜尋我自己來。結果貼回去以後，請它和文獻庫比對、刪掉已經下載過的，再排出優先順序。

我的研究是［題目］，核心構念是［A、B、C］。
請幫我擬 Consensus 和 Elicit 的查詢問題，各 4 組，
每組寫出：要找什麼、預期會找到哪類研究、用了哪些同義詞。
我搜完會把結果貼回來，到時請你：
1. 對照我附的文獻清單，刪掉已經有的
2. 依和我研究的關聯排優先序，並說明理由
3. 只根據我貼的內容判斷，不要補你記得的文獻

我踩過的坑

我請 AI 查「資管期刊有沒有我這個主題的實證研究」，它查不到，就建議把「資管期刊很少有這類研究」當成研究缺口。可是我認為 Computers & Education 這類教育科技期刊也算資管範疇，這樣算的話，相關研究其實不少。範圍沒先定好，AI 找出來的「缺口」可能只是它的範圍定得太窄。

3.3 文獻筆記（通用、進階）

先定筆記模板，再請 AI 照模板從 PDF 寫初稿。我的實證文獻模板分九節：速覽、研究背景、理論與研究模型、研究方法、研究結果、作者的結論與限制、我的批判、對本研究的用處、值得追讀的參考文獻；理論型、方法型文獻另有各自的模板。規則只有一條最重要：每個數字附 PDF 頁碼，查不到就寫查不到。寫完再請另一個 AI 回 PDF 驗收。

附件是［作者，年份］的 PDF，請照下面的模板寫文獻筆記。
規則：
- 每個統計數字（β、t、p、R²、樣本數）都附 PDF 頁碼
- 原文沒寫的寫「原文未報告」，不要推算或補值
- 原論文的構念照原文名稱寫，不要換成我研究的構念名稱；
  兩者的對應另外寫在「對本研究的用處」，並說明哪裡不同
［貼上模板］

驗收時換一個新對話或另一個 AI：

附件是一篇論文的 PDF 和一份文獻筆記。請只做核對，不要改寫：
逐一檢查筆記裡的每個數字、每個構念名稱、每個「作者認為」的句子，
在 PDF 裡找得到原文就標「符合」並附頁碼，找不到或不一致就標出來，
寫出原文實際寫什麼。

我踩過的坑

早期批次產生的筆記，有一篇把原論文的某個構念，寫成我研究裡名稱不同的另一個構念，AI 會把原文構念硬套成你的構念。還有一批筆記沿用舊的假說編號、統計數字只抄一部分。後來 AI 提出新的模板架構，我同意後照 PDF 重做核心文獻，每篇另外派 AI 回原文驗收；還沒重做的筆記，之後陸續改用新模板。

3.4 文獻缺口與「對本研究的幫助」（通用）

我第一次直接請 AI 寫，效果不好。之後打算先自己寫一句粗糙的想法，再請 AI 對照筆記檢查站不站得住。

我覺得［文獻］對我研究的幫助是：［你自己的一句話，粗糙也沒關係］。
請對照這篇的筆記檢查：
1. 我這句話有沒有寫得比原文強？原文實際做了什麼、沒做什麼？
2. 它和我的研究在情境、樣本、構念、方法上有哪些不同？
3. 依照上面兩點，給我 2 種改寫，並說明差在哪

我踩過的坑

我一開始直接問「這篇對我的研究有什麼幫助」，AI 給了兩版：第一版太像 AI 寫的，第二版借用它的發現。我先選了第二版，後來推翻，改問 AI 這篇和我用的是同一套理論模型，整體情境應該相似吧。AI 對照筆記才提醒我，那篇研究涵蓋的 AI 工具範圍比我的廣，情境並不相同，再給了新寫法。

3.5 寫作與改寫（通用）

我把寫作規範寫進 AI 每次都會讀的規則檔；用網頁版的話，可以存成一份清單，每次改寫時附上。其中一條是因果用詞：橫斷面問卷不能寫「導致」「造成」；寫「影響」是商管慣例，可以用，但全篇要和研究問題、結果章用同一套動詞（有些系所或指導教授另有規定，以你的系所為準）。也要請 AI 不要加「填補研究缺口」「具有重要意涵」這類空話。完整的規則見學術中文寫作紀律。

請檢查下面這段文字，只列出問題，不要直接改：
1. 因果用詞：我的研究是橫斷面問卷，有沒有寫成「導致、造成、使得」？
   引用別人的研究時，用詞有沒有超過那篇研究的證據強度？
2. 每個引用的說法，是否都能在我附的筆記裡找到依據？找不到的標出來
3. 有沒有空泛的句子（例如「具有重要意涵」「填補研究缺口」）？
4. 段落是不是第一句就先下結論？
［貼上段落］［附上相關筆記］

我踩過的坑

草稿裡一度用了一些自創的詞當核心主張，最早是誰寫的已經查不到，後來全部清掉。現在構念和路徑名稱一律先對照自己的術語表，不讓 AI 自己命名。

3.6 送出前的審查（通用、進階）

計畫書送口試或倫理審查前，請 AI 扮演第一次看這份文件的委員來挑毛病。最好換一個工具，或至少開新對話，不要讓寫的那個對話自己審。

你是第一次看這份碩士論文計畫書的口試委員，研究方法是［方法］。
請找出：邏輯漏洞、證據撐不住的主張、前後不一致的地方（數字、假說編號、構念名稱）。
每一點標出位置、說明為什麼是問題，並分成「一定要改」和「可以考慮」。
不用稱讚，也不用幫我改寫。

我踩過的坑

外部 AI 扮口委給了一長串建議，我沒有全收：只採納了兩題問卷題目的重寫，其他像拆維度、刪假說、加控制變數這幾項都婉拒了，理由也記下來。另外，送審文件裡一度混進 AI 的工作備註、工具名稱和內部檔案路徑，送出前要專門掃一次。

四、AI 在論文裡犯過的錯

這些都是後來回原文核對才抓到的。

AI 給的 怎麼處理
我要求把一張圖換成某個經典理論的模型圖，AI 依原論文的迴歸結果自己推出圖裡的關係，還標了「整理自」原論文 原文根本沒有這張圖。現在理論頁只放原文有、可以對照的圖。
某個理論的圖，把作者說沒有先後的兩個評估階段畫成有先後 AI 做圖檔核對時自己標出疑點，回原書查到作者明說兩者沒有先後，圖的箭頭要改。
引用一篇研究支持其中一條假說 讀全文後查無實據，推測是早期搜尋摘要的誤植。從此規定：沒對過 PDF 的引用不能當正式證據。
兩個 AI 對同一篇文獻的相關係數說法互相矛盾 回 PDF 才發現，其中一個把別的變項的相關係數套了上來。
自我核對時，把 5 個項目標成「已完成」 另一個沒看過前文的 AI 重新核對，5 項其實都沒做完。

五、進階：Claude Code 設定

這段給已經在用 Claude Code、Codex 這類工具的人。網頁版 AI 的使用者可以跳過，前面的原則一樣適用。

5.1 把論文資料夾變成 AI 的工作站

Obsidian 的筆記庫其實就是一個資料夾，Claude Code 可以直接讀寫。我在裡面開一個子資料夾當 AI 的工作站，每次都從那裡啟動。

論文資料夾/
├─ 03_文獻筆記/          # 一篇一檔，檔名用 Zotero 的 citekey
├─ 04_論文草稿/          # 依章節拆檔，改之前先確認要改哪一章
├─ 07_模板/              # 筆記模板，規定 AI 不能改
└─ claude-notes/         # AI 工作站，從這裡啟動
   ├─ CLAUDE.md          # 路由表＋紅線，每次對話自動載入
   ├─ 術語對照表.md       # 構念譯名的唯一權威
   ├─ session_log.md     # 每段工作的紀錄，下次開場自動讀
   └─ TODO.md
  • CLAUDE.md 只放三種東西：路徑、紅線（例如不得修改模板資料夾、構念一律用中文全名、橫斷面不寫因果）、做什麼事該讀哪個檔。細節放在別的檔案，用路徑指過去。
  • 術語只有一個權威檔。構念名稱、量表來源都寫在術語對照表，其他地方引用它，不重複抄。
  • 每段工作結束寫 session_log，下次開場用 hook 自動帶入最新一筆，AI 一開始就知道上次做到哪。

5.2 寫的和驗的分開

  • Claude Code 負責寫和改，Codex 負責第二意見。兩邊各自查同一件事，再比對分歧。
  • 驗收另外開一個沒看過前文的 agent，只給它驗收條件和檔案路徑，不給原本的推理過程，避免它被帶著走。
  • 「AI 說已經驗證過」不算驗證。可以比對的東西就自己找一組重跑。

5.3 把寫作規範做成 skill

我把課堂規範和寫作規則寫成 Claude Code 的 skill，寫作時自動套用。讀書和聽演講的心得只留自用；另外整理了三個通用的公開版，內容是自己寫的：

  • research-direction-finding：還沒有方向時，陪你收斂出一句話的研究想法
  • research-question-audit：已經有研究問題，檢查站不站得住
  • academic-writing-discipline：檢查中文學術寫作的因果用詞、構句、APA 格式、AI 腔

在 Claude Code 裡安裝：

/plugin marketplace add wayhong0928/mis-thesis-skills
/plugin install thesis-toolkit@mis-thesis-skills

原始碼和網頁版的安裝方式在 GitHub。

六、如果重來一次

  • 早一點找老師討論，理論先讀熟再請 AI 幫忙。我的題目方向是和老師討論出來的。
  • 第一天就開始存提示詞。我的紀錄在最早的找方向階段完全空白，事後只能靠回想。
  • AI 不會一次做對，要來回討論、修改，還要記下來。
