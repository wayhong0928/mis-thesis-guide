# 研究問題、假說與研究架構

> 從「一個現實世界的困擾」到「一個能被嚴謹回答的學術問題」，中間有一連串具體的翻譯動作。這一頁把它們拆開來講。

---

## 一、問題形塑：把實務問題抽象化

現實世界的問題通常長這樣：「我們公司導入新系統之後，同仁都不太願意用。」

這不是學術問題。它必須先被**概念化（conceptualisation）／抽象化**成一個學術問題，才能跟既有學術脈絡接軌、對話，並劃出既有知識的邊界。

彭明輝書中的比喻很傳神：把「海底潛水艇周邊之壓力分布」抽象成「有限長木棍在二維不可壓縮流體中之流場分析」。這個動作**保留了問題的核心，去除了次要的細節**，讓問題變得可以被精確而客觀地回答，同時讓研究的適用範圍變得更寬廣。

抽象化之後有兩個好處：

1. 可以引用學術界既有的理論、觀點與經驗來研究新問題，事半功倍；
2. 可以避免浪費力氣去研究跟既有學術知識重疊的部分。

!!! note "第一章講大範圍的概念，不要直接把研究情境帶進去"
    緒論的層次是「這個問題為什麼重要、學術界關心什麼」。具體的研究情境、樣本、施測對象是第三章的事情。緒論就把情境寫死，會讓論文看起來視野狹窄。

## 二、研究背景與動機（第一章第一、二節，約 5–10 頁）

背景與動機要回答一件事：**這個研究問題為什麼重要？**

而「重要」要落在兩個具體的問句上：

- 現有的研究**哪裡做得不好**？
- 哪裡**可以變得更好**？

寫法上的兩個提醒：

- 通常不會出現「我」「本國」這類主觀字眼進行論述。用「本研究」。
- 動機不是自傳。個人興趣可以是起點，但寫進論文的必須是學術與實務上的重要性。

## 三、研究目的與研究問題

### 3.1 兩者的分工

| | 回答什麼 | 對接什麼 | 寫法 |
|---|---|---|---|
| **研究目的** | 為什麼做這個研究 | 理論缺口 | 敘述段落 |
| **研究問題** | 具體要驗證什麼 | 統計分析／驗證程序 | 編號條列 |

台灣碩論的常見順序是目的在前、問題在後，中間用一句「根據上述研究目的，本研究提出以下待答問題」銜接。

研究目的通常以**實務目的**為主、**學術目的**為輔，而且要能呼應自己的研究設計。研究設計無法完成的目的不宜列入。

### 3.2 研究問題是研究架構圖的文字版

這是最實用的一句提示。對著研究架構圖，把每一組箭頭翻譯成文字問句，就是研究問題。

反過來說，如果你的研究問題無法在架構圖上找到對應的箭頭，那不是這個問題有問題，就是這張圖不完整。

### 3.3 核心禁忌：不要問「X 是否影響 Y？」

是非題的答案只有 yes / no，難以呈現效果大小與作用機制。口試委員也可能進一步追問研究問題如何承載預期貢獻。

好的研究問題問的是**程度**或**機制**，讓結果章的路徑係數、信賴區間、效果量等數值都成為答案的一部分。

| 研究設計 | 推薦句型 | 回答時要給什麼 |
|---|---|---|
| 橫斷面路徑 | 「X 對 Y 的預測效果為何？」 | β、p 值、效果量 |
| 中介效果 | 「M 在 X 與 Y 之間的中介效果為何？」 | 間接效果係數與 95% CI |
| 多前因比較 | 「各前因對 Y 的預測效果與相對貢獻為何？」 | 各路徑係數的大小比較 |
| 路徑比較 | 「A 路徑與 B 路徑的預測貢獻有何差異？」 | 路徑係數差異檢定 |
| 調節效果 | 「W 如何調節 X 與 Y 的關係？效果大小為何？」 | 交互作用項係數與效果量 |
| 量表開發 | 「量表呈現哪些因素結構？各維度信效度為何？」 | 因素結構、CR／AVE |
| 系統／方法開發 | 「相較於既有方法，本方法在 ⟨指標⟩ 上的表現為何？」 | 具體的績效比較數據 |

「X 是否顯著預測 Y？」這種次佳格式在台灣的碩論仍相當普遍，可以接受，但研究深度不如「效果為何」。若指導教授習慣這個格式，**在結果章務必補上效果量，不要只寫「顯著」**。

### 3.4 操作步驟：從假說回推研究問題

1. 先把所有假說列好（H1、H2、……）
2. 把同性質的假說歸組（直接效果 ／ 中介 ／ 序列中介 ／ 調節）
3. 每一組寫一題研究問題

這樣不會漏、不會重疊，也不會寫出「設計回答不了」的問題。多數優秀論文的研究問題都只有三題左右：直接效果一題、中介或調節一題、前因或情境一題。

### 3.5 常見錯誤

| 錯誤 | 問題出在哪 | 修正 |
|---|---|---|
| 「X 是否影響 Y？」 | 是非題，看不出深度 | 「X 對 Y 的預測效果為何？」 |
| 「是 A 還是 B？」 | 暗示二擇一競爭，但同時進入模型並不做巢套比較 | 「A 與 B 對 Y 的預測效果各為何？」 |
| 一題塞八條路徑 | 讀起來像假說清單 | 拆成 2–3 題，每題覆蓋一組同性質假說 |
| 橫斷面問「如何演變」 | 演變是時序主張，橫斷面答不了 | 改問預測效果或中介效果 |
| 假說寫「顯著影響」 | 「顯著」是檢定結果，不是假說內容 | 假說寫「正向影響」，結果章才說「顯著」 |
| 研究問題用因果動詞 | 橫斷面不能宣稱因果 | 見[學術中文寫作紀律](style.md)的替換表 |

## 四、研究假說：研究問題的學術版本

**研究假說是研究問題的學術版本。** 它更精確、帶方向性主張（正向或負向），而且是**待驗假設，不是結論**。

寫法要點：

- 假說寫「**正向影響**」或「**負向影響**」，不要寫「顯著影響」。
- 一條假說對應一條路徑，不要一條假說塞兩個主張。
- 每一條假說在文獻探討中都要有推導的依據，不能憑空冒出來。

### 4.1 假說未獲支持怎麼辦

務實的答案是：

1. **先確認測量與分析是否可信。** 檢查樣本、題項、資料蒐集與模型設定，但不能預設信效度一定有問題。
2. **把可信的零結果當成結果。** 假說未獲支持可能反映效果很小、邊界條件不同，或原本的理論預期不成立。
3. **區分結果與限制。** 有證據才指出設計缺口，不能為了交代不顯著結果而事後把一切歸因於方法。
4. **提出可檢驗的後續方向。** 未來研究建議要能由他人接續執行。

不得回頭修改或刪除原假說來掩蓋結果。若結果促成新的解釋，可明確標示為探索性或事後分析，保留原先的假說、分析計畫與未獲支持結果。

## 五、研究架構圖：把因果關係畫出來

**研究主張就是系統架構圖**，用來呈現可能的因果關係。它同時是：

- 研究問題的圖形版本
- 假說清單的視覺索引
- 口試簡報中最重要的一張投影片

### 5.1 三個要領

**要領一：模型越簡單越好。** 簡單才能聚焦在核心問題上。一個塞了十五個構念的模型，通常代表研究者還沒想清楚自己要問什麼。

**要領二：解釋模型時先講 Y，再講 X。** 先讓聽眾抓住「這個研究到底要解釋什麼結果」，再說明哪些因素在影響它。從架構圖的**右邊**開始講解，那才是研究的主題。

**要領三：把數據貼回架構圖。** 結果出來後，把顯著路徑的係數標回架構圖上，一眼就能看出哪個假說最重要、哪一條路徑最關鍵。這張「結果版架構圖」在口試時的說服力遠高於一張表格。

### 5.2 常見的架構型態

| 型態 | 結構 | 適用 |
|---|---|---|
| 兩階段（如科技接受類） | 前因 → 認知評估 → 意圖 | 採納、接受、使用意圖 |
| 三階段（刺激—有機體—反應） | 外部刺激 → 內在狀態 → 行為反應 | 介面設計、體驗、環境線索 |
| 中介模型 | X → M → Y | 想解釋「為什麼」X 會影響 Y |
| 序列中介 | X → M1 → M2 → Y | 有明確的機制串接順序 |
| 調節模型 | X × W → Y | 效果在不同情境／族群下不同 |

!!! warning "理論不能用拼的"
    整合兩個理論時，必須說明為何原模型不足以解釋你的研究情境。AI 很擅長把兩個理論的文字兜在一起，但兜不出真正的因果邏輯。整合的正當性來自「原模型的哪個假設在我的情境不成立」，而不是「這兩個理論都很紅」。

### 5.3 換了名詞，變數也要跟著改

**如果把研究對象換成其他東西，模型的變數也應該跟著修正，才不會是炒冷飯。**

例如「智慧機器人」是客服機器人、掃地機器人還是人形機器人？三者的特性與服務差異極大，能沿用的變數也不同。你必須抓到該產品／情境本身的特性，讓模型長出它自己的樣子。

## 六、操作型定義：所有的量測都從定義開始

這是研究設計中最關鍵、也最常被草率處理的一步。

> 所有的量測都從**定義**開始。先定義概念（構念），才能設計出真的測得到它的題目。

流程是兩層：

1. **概念型定義（conceptual definition）**：這個構念是什麼？（通常引用文獻的權威定義）
2. **操作型定義（operational definition）**：我要用什麼規則去量它？（題項、尺度、計分方式）

### 6.1 情境遷移：最常見的操作化陷阱

直接套用舊量表的題項到新情境，是最常見的錯誤。

- 舊情境（實體服務）的題項：「我能迅速找到所需資訊。」
- 新情境（行動服務）不能只替換名詞，可先用占位方式重問：「使用 ⟨特定功能⟩ 時，我能在 ⟨任務條件⟩ 下找到所需資訊。」

不同服務情境可能改變題項所指的任務、限制與判斷基準。AI 可以協助檢查改編語句，但**你必須親自確認新題項是否仍測量同一個構念**。這是構念效度的核心防線。

### 6.2 自我檢核

- [ ] 每個構念都有明確的概念型定義，並註明出處
- [ ] 每個構念都有對應的題項，題項來源可追溯
- [ ] 改編過的題項有說明改編理由與改編幅度
- [ ] 同一個構念在全篇使用同一個中文譯名，沒有混用
- [ ] 量表尺度（5 點／7 點）的選擇有理由（受測情境、參考文獻）

## 七、把一切串起來：研究設計的一致性檢查

一份設計良好的研究，下列五者應該一一對應、互相咬合：

```
研究目的 ──→ 研究問題 ──→ 研究假說 ──→ 研究架構圖 ──→ 統計分析方法
                                              ↓
                                        結果章的每一張表
                                              ↓
                                        結論章的逐題回應
```

**結論章節必須逐一回應研究問題，不可各說各話。** 常見的結構性缺陷是緒論提出問題，結論卻改談其他內容。

## 八、本頁重點回顧

- 實務問題必須先被抽象化成學術問題，才能跟文獻對話。
- 研究背景要回答「現有研究哪裡不好、哪裡可以更好」。
- **研究問題是研究架構圖的文字版；研究假說是研究問題的學術版本。**
- 不要問「是否影響」，要問「效果為何」「機制為何」。
- 從假說歸組回推研究問題，不會漏也不會重疊。
- 架構圖越簡單越好；解釋時從 Y 講起；結果出來要把係數貼回圖上。
- 所有的量測都從定義開始；換了情境，題項必須重新操作化。
- 目的 → 問題 → 假說 → 架構 → 分析 → 結論，必須一路咬合。
