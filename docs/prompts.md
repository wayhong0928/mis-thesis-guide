# AI 提示詞範本

!!! warning "使用前必讀"
    這些範本的目的是**提高提問的規格化程度**，不是把判斷外包出去。
    每一段 AI 產出都必須經過你自己的驗證。允許範圍與揭露方式會因系所、指導教授、研究倫理審查與投稿單位而異，請依實際規範確認（見[學術倫理與 AI 揭露](ethics.md)）。
    需要檢索或引用的提示詞，只有在工具確實具備外部查詢能力時才能使用；即使能查詢，也要開啟原文核對。
    貼入任何材料前，先移除姓名、單位、聯絡方式及可回推個人的組合資訊，並確認知情同意與資料處理規範允許使用該工具。
    範本中的 `⟨⟩` 都要換成你自己的內容。未補齊研究情境、預期產出與禁止事項，輸出通常無法使用。

---

## 零、所有提示詞都應該包含的三層

在貼上任何範本之前，先確認你的提問包含這三層（見[三層架構](ai-workflow.md)）：

本頁每一段提示詞都可以視為工作流其中一站的可重複指令：對應第一站（界定與檢索範圍）的是「一、題目探索」與「二、界定檢索範圍」；對應第二站（檢索與組織）的是「三、文獻工作」與「七、跨文獻整合」；對應第三站（設計與分析）的是「五、方法與分析」；對應第四站（寫作與檢查）的是「四、論證診斷」與「六、寫作」。想先看全貌，可對照[「一份可用的工作流」](ai-workflow.md#_9)；想知道如何把發想、找文獻、閱讀、筆記與彙整串起來，則見[「一個具體的工具鏈範例」](ai-workflow.md#111)。

```
【情境與輸入】我的研究目的是什麼？學界現況是什麼？我目前卡在哪？
【預期產出】我要什麼形式的產出？多長？什麼結構？
【邊界與作業原則】不准做什麼？引用怎麼處理？語氣與用語規範是什麼？
```

### 通用的作業原則段落（建議固定貼在每次提問的最後）

```
【邊界與作業原則】
1. 不確定的資訊請明確標示「不確定」，不要推測補全。
2. 引用任何文獻時，必須提供作者、年份、標題、期刊或出版單位。
   若無法確認該文獻真實存在，請明說，不要生成。
3. 全程使用台灣繁體中文的學術用語：
   資料（非數據）、透過（非通過）、迴歸（非回歸）、資訊（非信息）、
   使用者（非用戶）、演算法（非算法）、人工智慧（非人工智能）、
   收斂效度（非聚合效度）、區辨效度（非判別效度）、橫斷面（非橫截面）。
4. 不要使用「首先／其次／再次／最後」的機械式排列，
   不要用「綜上所述」「值得注意的是」「換句話說」收尾或轉折。
5. 描述橫斷面研究的結果時，只能使用「預測」「相關」，
   不得使用「導致」「造成」「引發」等因果動詞。
6. 如果我的問題本身有問題（範圍太寬、概念不清、設計答不了），請先指出來，再回答。
```

## 一、題目探索

### 1.1 環境掃描

```
【情境與輸入】
我是資訊管理研究所碩士生，正在尋找論文題目。
我感興趣的大方向是：⟨主題，例如「組織內部導入 AI 工具後的協作變化」⟩。
我目前知道的是：⟨你已經讀過的兩三件事⟩。
我還不知道的是：⟨你自覺的空白⟩。

【預期產出】
請產出一份「寬而淺」的領域地圖，包含：
1. 這個大方向底下主要的研究子題有哪些類別（3–6 類）
2. 每一類的代表性研究取向與常用理論
3. 每一類目前的主要爭議或未解問題
4. 這個領域近五年的發展趨勢
長度控制在 1500 字以內，不要條列超過三層。

【邊界與作業原則】
（貼上通用作業原則）
另外：本階段不需要窮盡文獻，重點是讓我看見版圖，不要一次給我上百篇。
```

### 1.2 矛盾偵測（找研究缺口最有效的一招）

```
我想找出 ⟨研究主題⟩ 領域中，不同研究之間**結論相互矛盾**的地方。

請整理：
1. 有哪些議題上，不同研究得出了相反或不一致的結論？
2. 每一組矛盾中，雙方分別使用了什麼樣本、什麼方法、什麼情境？
3. 造成矛盾的可能原因是什麼？（樣本差異／方法差異／情境差異／測量差異）
4. 哪一組矛盾最有可能透過新的研究設計來釐清？為什麼？

對於每一個你提到的研究，請提供可查證的作者與年份。
無法確認的請標示「待查證」，不要生成看起來合理但不確定的引用。

（貼上通用作業原則）
```

---

### 1.3 研究點子的價值與可行性審查

這一則比較長，但它是最值得存成範本的一則：**在投入三個月之前，先讓一個刻意挑剔的角色把你的構想打一輪。** 前半段是角色設定（每次沿用），後半段是五個檢查步驟。

```
【角色】
請扮演一位在 ⟨你的領域⟩ 有雙重身分的資深專家：
(1) 學術面：頂級期刊的審稿人，對邏輯與方法論標準極高，重視「最省力的創新」與風險控管；
(2) 實務面：資深顧問，痛恨空泛理論，要求研究對實務有決策價值。

【風格】
批判、直接、不說好聽話。主動扮演惡魔的代言人，指出我看不到的盲點。
遇到不確定的資訊，直接說「不知道」，不要提供推測性的答案。
任何引用都要能查證，查不到就說查不到。

【判斷基準】
- 報告是整理「已知」，研究是探討「未知」。如果我的點子只是整理資料，直接說「這是報告，不是研究」。
- 拒絕無意義的換場域，除非我能證明新場域有獨特的變數或情境限制。
- 「有趣」＝跟理所當然不一樣，或找出既有文獻的矛盾。
- Outcome First：先講 Y（結果），再講 X（原因）。
- 任何研究都必須有備胎方案，並評估資料取得的現實難度。

【我的構想】
研究問題：⟨貼上⟩
依變數 Y：⟨貼上⟩
自變數 X 與中介／調節：⟨貼上⟩
理論基礎：⟨貼上⟩
打算用的方法與樣本：⟨貼上⟩

【請依序執行五個步驟】
1. 價值審查：這個題目是不是換湯不換藥？如果假設成立，會讓人意外嗎？
   它屬於「舊瓶新酒」「新瓶舊酒」還是「雁行」？
2. 理論解構：Y 定義清楚嗎？為什麼這個 Y 重要？X 的選擇有沒有堅實的理論依據？
3. 方法論審計：這個設計真的能回答這個問題嗎？指出潛在的邏輯謬誤
   （倒果為因、樣本偏差、共同方法變異）。
4. 可行性與替代方案：資料或受試者容易取得嗎？最可能卡關的環節在哪？
   如果收不到足夠樣本或結果不顯著，「退而求其次」的結論可以往哪個方向寫？
5. 具體建議：從學術與實務兩個角度，提出下一步的修改建議。
```

!!! warning "這則提示詞的用法與極限"
    它產出的是**待查證的問題清單**，不是結論。AI 對「什麼算有貢獻」的判斷來自訓練資料的平均值，不等於你的系所與指導教授的標準。
    正確用法是：把它挑出來的問題，一條一條拿去問指導教授、拿去對照文獻。**它的價值在於幫你想到你沒想到的問題，不在於幫你回答。**
    第 5 步的建議務必自行判斷；一個 AI 覺得可行的研究設計，可能在你的系所根本收不到樣本。

## 二、界定檢索範圍：納入與排除準則

```
請扮演研究方法顧問，協助我把模糊的研究方向，收斂成一組可以寫進方法章的
納入準則（inclusion criteria）與排除準則（exclusion criteria）。

我目前的想法是：⟨用你自己的話描述，允許混亂⟩

請透過提問逐步協助我釐清下列項目，**一次只問我一組問題**，
等我回答之後再問下一組：

【納入準則】
   - 研究對象是誰？（年齡、身分、經驗門檻）
   - 情境／場域是什麼？（平台、產業、任務類型）
   - 核心變項有哪些？
   - 文獻範圍？（年份區間、期刊等級、語言）
   - 研究設計？（只收實證研究？含質性嗎？含預印本嗎？）

【排除準則】
   - 哪些干擾變項不在本研究範圍內？
   - 哪些族群或情境不算數？
   - 哪些文獻類型要排除？（評論文章、會議摘要、未經同儕審查者）

當我回答得太模糊時，請直接指出來並追問，不要幫我補完。

最後請輸出兩份東西：
1. 一份完整的納入／排除準則清單
2. 一段供我核對並自行重寫的方法章草稿（150 字以內）
```

!!! tip "為什麼要它同時產出方法章的敘述"
    納入排除準則本來就是方法章要寫的內容。**先寫準則再檢索，等於邊做邊寫論文**；
    先檢索再回頭補準則，通常會發現自己說不清楚為什麼漏了某些文獻。

## 三、文獻工作

### 3.1 文獻事實查核（三步查核的第二步）

```
以下是一段包含文獻引用的文字。請執行事實查核：

【待查核文字】
⟨貼上文字⟩

【任務】
1. 抽出所有被引用的文獻（作者、年份、標題、期刊、DOI）
2. 逐一驗證每一篇是否真實存在
3. 對每一篇標示：
   ✅ 通過（可確認存在且資訊正確）
   ⚠️ 不完整（存在但部分資訊有誤，請指出哪裡有誤）
   ❌ 虛構（查不到，或明顯是拼湊出來的）
4. 以表格輸出

【重要】
- 不要為了填滿表格而猜測。查不到就標 ❌。
- 你只能確認「文獻是否存在」，不能確認「文獻是否真的說了那句話」。
  請在輸出的最後提醒我這一點。
```

### 3.2 文獻矩陣

```
我要建立一份文獻矩陣來尋找研究缺口。

【我的研究方向】⟨一句話⟩
【我打算用的兩個維度】
  維度 A：⟨例如「研究方法：質性 / 量化 / 混合」⟩
  維度 B：⟨例如「研究對象：學生 / 職場工作者 / 特定產業」⟩

【我已讀過的文獻】
⟨列出 5–15 篇，含作者年份與一句話摘要⟩

請：
1. 把我讀過的文獻填進矩陣
2. 指出哪些格子是空的
3. 對每一個空格，評估它是「真缺口」還是「沒有研究價值的組合」，並說明理由
4. 提出一份「補強清單」：接下來我最需要補哪一類文獻，優先順序如何

（貼上通用作業原則）
```

### 3.3 從教授批註反推補強方向

```
【我的論文草稿片段】
⟨貼上⟩

【指導教授的批註意見】
⟨原文照貼，不要自己改寫⟩

請扮演研究教練，執行兩項診斷：

一、概念分析診斷
   教授的每一則意見，實際上在質疑什麼？
   （是概念定義不清？論證跳步？文獻不足？方法不合理？還是表達問題？）
   請逐條分析，不要籠統帶過。

二、補強需求診斷
   針對每一則意見，我需要補什麼？
   - 需要補文獻的：說明要補哪一類文獻，以及建議的搜尋關鍵字
   - 需要補論證的：指出斷鏈的位置與需要補上的中間命題
   - 需要補資料的：說明需要什麼證據

最後輸出一份【文獻探討補強報告】，含優先順序。
```

## 四、論證診斷

### 4.1 邏輯斷鏈檢查（研究教練角色）

```
請扮演嚴格的論文審查者，對以下段落進行**論證結構診斷**。

【待診斷文字】
⟨貼上一節，建議 1500 字以內⟩

【任務】
1. 從文本中抽取出所有的命題（主張），逐一編號
2. 分析命題之間的推理關係（哪些是前提、哪些是結論、依據什麼推出）
3. 用文字描述整個論證結構
4. 檢測下列四種邏輯斷鏈，逐一指出位置：
   - 跳步：推理過程中缺乏論證就直接跳過
   - 隱含前提未交代：論述成立的條件未明確說明
   - 概念漂移：同一名詞在不同段落指涉不一致
   - 前後矛盾：前後段落論點彼此衝突
5. 針對每一個問題，提出具體的修正建議（要改哪一句、怎麼改）

請直接指出問題，不需要先稱讚。
```

### 4.2 魔鬼代言人

```
請扮演一位對這個領域非常熟悉、而且會嚴格追問的口試委員。

【我的研究】
研究問題：⟨貼上⟩
研究架構：⟨文字描述你的架構圖⟩
研究方法：⟨方法、樣本、分析工具⟩
主要發現：⟨貼上⟩

請針對下列每一項，各提出 2–3 個最尖銳的問題：
1. 為什麼用這個理論而不用其他理論？
2. 這個研究架構有沒有牽強之處或弱點？
3. 樣本與抽樣方式有什麼問題？
4. 這個方法的基礎假設，在我的情境下成立嗎？
5. 有沒有其他解釋可以解釋我的結果？
6. 這個研究對學術界的貢獻，真的夠嗎？

問完之後，請針對每一個問題，指出「一個好的回答應該包含什麼要素」，
但不要替我寫答案。
```

### 4.3 理論縫合診斷

```
我的研究同時用到兩個理論，但我不確定它們接不接得起來。

理論 A：⟨名稱與核心主張⟩
理論 B：⟨名稱與核心主張⟩
我打算讓它們在模型中的關係是：⟨描述⟩

請回答：
1. 這兩個理論之間，是否存在一個明確的**連結機制**？如果有，是什麼？
2. 這個連結在既有文獻中有沒有被討論過？（請提供可查證的文獻，查不到就說沒有）
3. 兩個理論的**基礎假設**是否相容？有沒有互相衝突的前提？
4. 如果要說服口試委員這個整合是必要的，我必須論證什麼？
5. 如果它們其實接不起來，請直接告訴我，並說明理由。

不要為了配合我而硬找連結。接不起來就說接不起來。
```

## 五、方法與分析

### 5.1 方法選擇的壓力測試

```
我打算用 ⟨方法⟩ 來回答這個研究問題：⟨研究問題⟩

請對這個選擇進行壓力測試：
1. 這個方法的**基礎假設**有哪些？我的研究情境符合嗎？
2. 有哪些**替代方法**可以回答同一個問題？各自的優缺點是什麼？
3. 相較於替代方案，我的選擇在什麼條件下才是更好的？
4. 這個方法最可能被口試委員追問的三個點是什麼？
5. 如果我堅持用這個方法，我必須在論文中預先處理哪些疑慮？

請用表格呈現第 2 點的比較。
（貼上通用作業原則）
```

### 5.2 操作型定義檢查

```
【構念名稱】⟨例如「知覺易用性」⟩
【我採用的概念型定義】⟨貼上，含出處⟩
【原始量表的題項】⟨貼上⟩
【我的研究情境】⟨描述，特別是與原量表情境的差異⟩

請協助我檢查：
1. 原量表的題項中，哪幾題在我的情境下會失去原意或產生歧義？為什麼？
2. 針對這些題項，改編的方向應該是什麼？（不要直接給我改好的題目，
   先告訴我改編時必須保留哪個核心語意）
3. 改編後可能傷害構念效度的風險是什麼？
4. 如果要在論文中辯護這些改編，我需要提出什麼證據？

最後才提供改編題項的草案，並逐題標註「改了什麼、為什麼」。
```

### 5.3 結果詮釋的自我挑戰

```
【我的分析結果】
⟨貼上路徑係數表／統計結果⟩

【我目前的詮釋】
⟨貼上你打算怎麼寫⟩

請檢查：
1. 我的詮釋有沒有超出證據能支持的範圍？逐句標出越線的地方。
2. 同一組數據，有沒有其他合理的替代解釋？
3. 有哪些結果我沒有討論到，但口試委員一定會問？
4. 不顯著的路徑，我打算怎麼處理？有沒有更誠實的寫法？
5. 我使用的動詞，是否符合橫斷面研究的紀律？

請直接標出問題句子並提供修正版本。
```

## 六、寫作

### 6.1 去 AI 感自檢

```
請對以下段落進行「AI 生成痕跡」診斷。

【待檢查文字】
⟨貼上⟩

請逐項檢查並列出具體位置：
1. 句長是否高度一致？（列出連續三句長度相近的位置）
2. 段落結構是否都是「主張→證據→小結」的三明治？
3. 有沒有「首先／其次／最後」連用超過三段？
4. 每段開頭是否都有「此外」「然而」「因此」？
5. 「不是 X 而是 Y」句型出現幾次？
6. 破折號用在哪些地方？哪些可以改成逗號或括號？
7. 有沒有「具有重要意涵」「填補研究缺口」這類空泛的讚揚式結語？
8. 同一個構念有沒有被換成不同名稱？
9. 有沒有大陸用語混入？（逐一列出）
10. 有沒有「可能或許大概也許」這類過度 hedging？

**只診斷，不要改寫。** 我要自己改。
```

### 6.2 「送達」測試

```
請扮演一位「熟悉研究方法但不熟悉我這個研究主題」的碩士生讀者。

【待測試段落】
⟨貼上⟩

請告訴我：
1. 讀完之後，你認為這一段在講什麼？（用你自己的話複述）
2. 有哪些句子你讀了兩次以上才懂？
3. 有哪些術語你不知道意思，而作者沒有解釋？
4. 有哪些地方你覺得論述牽強或跳躍？
5. 如果要你用一句話總結這一段的主張，你會怎麼寫？

不要客氣，也不要幫我補完我沒寫清楚的意思。
你讀不懂的地方，就是我沒寫清楚的地方。
```

### 6.3 摘要要素檢核

```
【我的論文】
研究主題：⟨⟩
既有文獻的關鍵不足：⟨⟩
我採用的方法：⟨⟩
最關鍵的研究成果：⟨⟩
結論：⟨⟩

請檢查這五個欄位是否足以支撐摘要，逐項指出缺漏、重複、過度宣稱與不一致之處。再提供一份「句子功能清單」與刪減建議，讓我自行撰寫摘要。不要生成可直接提交的完整摘要，也不要補寫我未提供的研究內容。
```

### 6.4 簡報結構檢查

```
以下是我要在 ⟨計畫書口試／進度報告／研討會⟩ 上報告的內容。
時間 ⟨N⟩ 分鐘，聽眾是 ⟨誰⟩。

⟨貼上你的論文摘要或各章重點⟩

請幫我檢查簡報的結構，依序回答：
1. 這份報告聽眾「必須帶走」的唯一一個觀點是什麼？用一句話說。
2. 依照「情境 → 衝突 → 解決」的順序，前三張投影片各該說什麼？
3. 列出建議的投影片清單（每張一行），並為每一張寫一個**結論句標題**，
   不要用「研究方法」「研究發現」這種名詞標題。
4. 指出哪些內容應該刪掉；不支撐第 1 題觀點的內容一律算雜訊。
5. 哪一張投影片最可能被追問？我該準備什麼備用投影片？

不要幫我寫投影片內容，只處理結構與標題。
```

## 七、跨文獻整合（周期化工作流）

```
以下是我這週讀的 ⟨N⟩ 篇文獻的筆記：

⟨逐篇貼上：作者年份、研究問題、理論、方法、樣本、主要發現⟩

請執行跨文獻整合，輸出：
1. **共同主題**：這些研究共同關心的問題是什麼？
2. **方法上的共通與差異**：它們的設計有什麼一致的地方？哪裡分歧？
3. **結論的矛盾之處**：有沒有互相衝突的發現？可能的原因是什麼？
4. **共同的研究限制**：它們都沒處理什麼？
5. **浮現的研究缺口**：綜合以上，有哪些問題還沒被回答？
6. **對我的研究的意義**：⟨我的研究方向是……⟩，這批文獻中哪幾篇最值得深讀？為什麼？

第 5 點請特別說明：這些缺口是「真的沒人做」，
還是「可能做過但失敗所以沒發表」？如何區分？
```

## 八、不該用的提示詞

以下這些請不要用，理由見[學術倫理與 AI 揭露](ethics.md)：

| ❌ 不該做 | 為什麼 |
|---|---|
| 「幫我生成 300 筆符合這個分布的問卷資料」 | 造假，是最嚴重的學術不端 |
| 「幫我改寫這段，讓它通過 AI 偵測」 | 規避誠信審查 |
| 「幫我寫第二章文獻探討／可直接提交的方法章或摘要」 | 代寫；也可能補入你未查證的內容 |
| 「幫我調整這些數據讓假說成立」 | 變造 |
| 「我不知道這篇文獻寫什麼，你幫我摘要後我直接引用」 | 未讀原文就引用，無法說明原文的條件與限制 |
| 把受訪者逐字稿原文（含姓名、單位）直接貼給 AI | 個資與知情同意問題 |

## 九、把常用提示詞包成自己的 Claude Code skill

當你對同一類任務連續第三次貼上相同提示詞，就值得把它包成 skill。例如「檢查橫斷面研究的因果動詞是否越線」或「檢查文獻矩陣格式」，規則穩定、操作重複，打包後比每次複製貼上省事。

Claude Code skill 的基本概念與放置位置，見[AI 代理工具懶人包的「Skill 的最小結構」](ai-agents.md#23-skill)。該節的既有範例著重示範 `description`；本節補上 `name` 與腳本用法，整理成可直接改寫的完整骨架。最小版本是一個資料夾，裡面至少有 `SKILL.md`：

- 檔案開頭的 frontmatter 至少寫 `name` 與 `description`。`description` 要清楚說明「什麼情況下該使用這個 skill」，因為這段文字會影響 Claude 是否判斷它適用於目前任務。確切觸發機制仍以你使用版本的官方文件為準，**待查證**。
- `SKILL.md` 本體放檢查邏輯、提示詞內容與規則。你可以直接拿本頁某一段範本改寫，但要刪掉只適用單次工作的背景資料。
- 如果工作需要機械化檢查，例如用 `grep` 找出特定詞彙，可以把腳本放在同一個 skill 資料夾，並在 `SKILL.md` 寫清楚何時執行、如何判讀結果。

下面把「因果動詞自檢」改成最小骨架。資料夾名稱可自訂，例如 `cross-sectional-causality-check/`；其中建立一個 `SKILL.md`：

```markdown
---
name: cross-sectional-causality-check
description: 檢查橫斷面研究文字是否把相關或預測結果誤寫成因果關係時使用。
---

# 橫斷面研究因果動詞檢查

檢查使用者指定的文字或檔案，找出「導致、造成、引發、促使、驅動」等因果動詞。

## 規則

1. 逐句列出疑似越線的原文與位置。
2. 判斷該句證據是否只來自橫斷面資料；無法判斷時標示「待查證」，不要自行推定研究設計。
3. 若證據只能支持關聯或預測，建議改用「相關、預測、同向變動」等詞。
4. 只做診斷與修改建議，不改動原檔，除非使用者明確要求。

## 輸出格式

用表格列出：位置、原句、問題、建議用詞、判斷依據。
```

skill 是 Claude Code 或其他明確支援 skill 的 Claude 介面所用的機制。如果你平常使用 ChatGPT、Gemini，或不支援 skill 的純網頁對話，本頁的靜態提示詞仍是最泛用的做法，不必勉強轉換。
