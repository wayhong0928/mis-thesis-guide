# 論文筆記庫範本：下載就能用的 Obsidian 筆記庫

> 這頁介紹 [thesis-notes-template](https://github.com/wayhong0928/thesis-notes-template)：一個下載解壓縮、用 Obsidian 打開就能用的論文筆記庫。裡面有五種筆記的模板、文獻筆記的填寫規則、一張文獻矩陣表，和五段可以直接貼給 AI 的提示詞。
>
> 範本的模板以[文獻管理與知識庫](tools-knowledge.md)第四節的五種筆記為底，再加上一份碩士論文實際做下來踩過的坑。repo 裡沒有任何 AI 工具的設定檔，提示詞只是文字，設計上不依賴特定 AI 工具；實際測過哪些，見第七節。

---

## 一、跟一小時上手的模板有什麼不同

[網頁版一小時上手](ai-quickstart.md)第五節有一份精簡的文獻筆記模板，適合第一週先試試看。這個範本是完整版，差別如下：

| | 一小時上手第五節 | 論文筆記庫範本 |
|---|---|---|
| 筆記種類 | 只有文獻筆記 | 文獻、構念、理論、方法、假說推演五種 |
| 文獻筆記模板 | 一份通用版 | 實證型、理論型、方法型三份 |
| 填寫規則 | 寫在提示詞裡的三條 | 一份獨立的規則檔：頁碼、數字、TBD、證據強度用詞、連結條件、自我核對清單 |
| 提示詞 | 一段寫筆記的提示詞 | 五段，每段有網頁版和 CLI 版 |
| 適合 | 還沒決定要不要用筆記軟體 | 已經要開始累積第二章材料 |

兩者不衝突。先用一小時上手的模板寫幾篇，覺得欄位不夠用了再換範本，舊筆記照新模板補欄位就好。

## 二、下載與開啟

1. 到 [thesis-notes-template](https://github.com/wayhong0928/thesis-notes-template) 按綠色的 **Code** → **Download ZIP**，解壓縮到你放論文檔案的地方。
2. 打開 Obsidian，選「開啟資料夾作為儲存庫」（Open folder as vault），選剛解壓縮的資料夾。
3. 先讀 `00_總覽/開始使用.md`，再打開三份填好的示範：`03_文獻筆記/Davis1989`、`02_變數/PU_知覺有用性`、`05_假設推演/知覺有用性→使用意圖`。

範本不需要裝任何 Obsidian 外掛。文獻矩陣用的是核心外掛 Bases，Obsidian 版本太舊會打不開，先更新到最新版。

## 三、裡面有什麼

| 位置 | 內容 |
|---|---|
| `00_總覽/開始使用.md` | 打開第一眼看的短版說明 |
| `00_總覽/研究設計速查.md` | 研究問題、假說表、構念對假說。全庫只有這裡和推演卡記假說編號 |
| `00_總覽/術語表.md` | 構念的標準中譯、英文原名、量表來源、文獻中的別名 |
| `00_總覽/文獻筆記填寫規則.md` | 自己寫或請 AI 寫筆記都照這份 |
| `00_總覽/提示詞.md` | 第六節的五段提示詞 |
| `00_總覽/文獻矩陣.base` | 所有文獻筆記排成一張表，可以看哪些還沒核對、哪些連結斷了 |
| `01_理論` 到 `06_方法` | 各放一種筆記，每個資料夾的 `說明.md` 寫了檔名規則 |
| `07_模板` | 理論、變數、文獻筆記三型、假說推演、方法，共 7 份 |

命名規則：構念卡用 `縮寫_中文名`（`PU_知覺有用性`），理論卡用 `序號_理論名`，文獻筆記用 Zotero 的 citekey（`Davis1989`），推演卡用關係命名（`知覺有用性→使用意圖`）。

## 四、幾個設計決定，以及背後的理由

這些設計都來自實際寫論文時出過的問題。

| 出過的問題 | 範本的做法 |
|---|---|
| 假說改版、重新編號好幾次，舊編號一直殘留在文獻筆記和其他檔案裡 | 文獻筆記不寫你自己的假說編號，只連到構念卡。編號只出現在 `研究設計速查.md` 和推演卡的 `hypothesis` 欄，推演卡檔名也不帶編號。重新編號時只改這兩處 |
| 原論文的構念被寫成自己研究的構念名稱，兩者其實定義不同 | 原論文的構念照原文翻，對應關係只寫在變項表的「對應本研究構念」欄，並寫出相同與不同之處 |
| 名稱不同、概念相同的構念各開一張卡，第二章重複寫 | 術語表有「文獻中的別名」欄，構念卡有「同義或近義名稱」，同一個概念只開一張卡 |
| 統計數字只挑幾個寫，或把量尺不同誤判成原文自相矛盾 | 數字照原文抄並附 PDF 頁碼，結果表列出每一條假說；只有同一個量在原文兩處對不上才算矛盾 |
| 引用的動詞比研究設計能支持的更強 | 規則檔附證據強度用詞表：實驗、縱貫寫「影響」，橫斷面寫「預測」「相關」，質性寫「反映」 |
| 假說只有鄰近構念的證據，口試時被問到 | 推演卡有「證據型態」欄：直接實證、類比實證、純理論推導 |
| citekey 亂掉，筆記改名後連結全斷 | README 的第一週清單：寫第一份筆記前先設好 Better BibTeX 的 citekey 公式，定了就不改 |
| AI 寫的筆記，同一個對話自己看不出錯 | 提示詞分成「寫」和「核對」兩段，核對一定開新對話 |

寫第二章時照 repo `00_總覽/開始使用.md` 開頭的一句話原則：讀的時候面對論文卡，寫的時候面對構念卡。

## 五、文獻筆記填寫規則重點

完整規則在 repo 的 `00_總覽/文獻筆記填寫規則.md`，最常用到的是這幾條：

- **頁碼**：每個數字、定義、作者主張都附 `（PDF p. 5）`，指 PDF 檔的第幾頁，不是期刊印的頁碼。
- **TBD 和 N/A**：適用但原文找不到填 `TBD`，這類論文本來就不會有的欄位填 `N/A`。不用推測或記憶補。
- **原文自己對不上**：每個版本都記下並各附頁碼，加註「原文數字不一致」，不要自己挑一個。
- **作者說的和你說的分開**：缺口、限制只寫作者自己寫的；你的看法放「我的批判」。
- **`連結的概念筆記`**：只連實際存在、而且跟原論文構念指同一件事的構念卡。只是理論上相關的不連。
- **`verified`**：回 PDF 核對過才填日期。文獻矩陣的「還沒核對」分頁會列出空著的筆記。

!!! tip "示範筆記可以拿來對照"
    `Davis1989` 是先用第六節第 2 段請 Claude Code 寫、再用第 3 段核對並回 PDF 逐項修正的版本。除了 `[[PEOU_知覺易用性]]` 故意留成斷掉的連結（示範文獻矩陣怎麼抓），每一欄都照規則填了，也示範幾種容易漏的寫法：原文找不到的欄位填 TBD、原文自己前後對不上時兩個版本並列、範例研究的推論跟原文的發現分開寫。用第六節第 2 段請 AI 寫筆記後，可以拿它對照 AI 的產出。

## 六、五段提示詞

下面跟 repo 裡的 `00_總覽/提示詞.md` 內容相同。網頁版一次處理一篇，PDF 自己上傳；CLI 版在筆記庫資料夾開 Claude Code 或 Codex，給一份 citekey 清單就能一篇接一篇處理。CLI 版會讀寫你電腦上的檔案，第一次用之前先看[Claude Code／Codex 一小時上手](ai-quickstart-agent.md)第三節的權限設定。

`⟨ ⟩` 裡的字換成你自己的內容。

### 6.1 快速設定：從計畫書填出術語表和研究設計速查

**什麼時候用**：剛建好筆記庫，手上有計畫書草稿（哪怕很粗）。

**網頁版**：

```text
附件是我的論文計畫書草稿，還有兩份空白表格：術語表.md、研究設計速查.md。
請根據計畫書填出這兩份表格的初稿：
1. 術語表：列出計畫書裡的每個構念，填標準中譯、英文原名、量表來源。
2. 研究設計速查：填研究問題、假說表（編號、關係）、構念對假說。
規則：
- 只用計畫書寫到的內容。計畫書沒寫的欄位留空，不要自己補，也不要依你對這個領域的知識推測。
- 計畫書前後不一致的地方（例如同一個構念用了兩個名字、假說編號對不上），不要自己挑一個，列在最後的「待確認」清單。
- 輸出兩份完整的 Markdown，讓我直接貼回檔案。
```

**CLI 版**：

```text
讀 ⟨計畫書路徑，.md 或 .docx⟩，填寫 00_總覽/術語表.md 和 00_總覽/研究設計速查.md 的初稿。
規則：
- 只用計畫書寫到的內容。計畫書沒寫的欄位留空，不要自己補。
- 把兩份檔案裡標「（示範）」的列刪掉，換成我的內容。
- 計畫書前後不一致的地方不要自己挑一個，最後列成「待確認」清單回報給我。
- 只改這兩個檔案。
```

**AI 回來後你要檢查**：每個構念的英文原名和量表來源，回計畫書對一次；「待確認」清單逐條自己決定。


### 6.2 寫文獻筆記

**什麼時候用**：讀完（或至少讀過一遍）一篇論文，要留下筆記。

**網頁版**：

```text
附件是一篇論文的 PDF。請照專案檔案裡的「文獻筆記填寫規則」寫一份文獻筆記：
1. 先判斷這篇用實證型、理論型還是方法型模板，說明理由。
2. 照該模板的章節與欄位填寫，章節標題不改、不新增。
3. 讀完全文再動筆，不要只讀摘要和結論。
4. 每個數字、定義、作者主張都附 PDF 頁碼（PDF 檔的第幾頁）。原文找不到的填 TBD，不適用的填 N/A，不要用你記得的內容補。
5. 原論文的構念照它自己的定義翻譯，不要改成我研究的構念名稱。
6. 「對我的研究的用處」那一節（實證型第八節、理論型第九節，方法型是第六節「在本研究的用法」），以及實證型變項表的「對應本研究構念」欄，依專案檔案裡的研究設計速查寫成草稿，每句開頭標〔推論〕。
7. 不要寫我研究的假說編號。
8. 最後另外列出：你實際讀到的 PDF 頁碼範圍（第幾頁到第幾頁）、填了 TBD 的欄位、你不確定的地方。
輸出完整的 Markdown（含 frontmatter），檔名用 citekey：⟨citekey⟩。
```

**CLI 版**：

```text
你在一個 Obsidian 論文筆記庫的根目錄。請依序為下列 citekey 各寫一份文獻筆記：
⟨citekey，一行一個⟩

先讀 00_總覽/文獻筆記填寫規則.md、00_總覽/術語表.md、00_總覽/研究設計速查.md。
每一篇照這個流程：
1. PDF 在 _pdf/{citekey}.pdf。如果 _pdf/{citekey}.txt 還不存在，用 Python 的 PyMuPDF（pip install pymupdf）把 PDF 轉成純文字，每頁開頭加一行「===== PDF p. N =====」（N 從 1 起算），存成 _pdf/{citekey}.txt。
2. 讀完整份文字檔再動筆，不能只讀摘要和結論。表格在文字檔裡看不懂時，回去看那一頁 PDF。
3. 依規則第一節選模板，照 07_模板/ 對應檔案的結構寫到 03_文獻筆記/{citekey}.md。{{title}} 換成論文標題，模板裡的 HTML 註解刪掉。
4. 頁碼一律用文字檔的分頁標記數，標之前回文字檔確認那句話在哪一頁，不要憑大概位置標。
5. 「對我的研究的用處」那一節（實證型第八節、理論型第九節，方法型是第六節「在本研究的用法」），以及實證型變項表的「對應本研究構念」欄，依研究設計速查寫成草稿，每句開頭標〔推論〕。
6. 不要寫我研究的假說編號。verified 欄留空，要等另一個對話核對後才填。
7. 照規則第六節自我核對。
處理完全部之後回報，每篇一段：用了哪一型模板、實際讀到的 PDF 頁碼範圍、填了 TBD 的欄位、你不確定的地方。
只建立或修改 03_文獻筆記/ 和 _pdf/ 裡的檔案。不要用你記得的內容補原文沒寫的東西。
```

**AI 回來後你要檢查**：頁碼範圍是不是涵蓋全文；〔推論〕的句子逐句自己改寫或刪掉，改完把〔推論〕拿掉；然後跑第 3 段核對。


### 6.3 核對文獻筆記（一定要開新對話）

**什麼時候用**：AI 寫完一份筆記之後。寫的那個對話看不出自己的錯，要換一個新對話，最好換一個模型。

**網頁版**：

```text
附件是一篇論文的 PDF，以及別人根據它寫的文獻筆記。請只做核對，不要改寫筆記。
逐條檢查，每條回報「通過／不通過」，不通過要寫出筆記的原句、PDF 的原句和頁碼。下面用的是實證型筆記的章節名稱；理論型、方法型就找對應的那一節，沒有對應的項目回報「不適用」。
1. 抽 10 個數字回 PDF 對，要一字不差（數字少於 10 個就全查）。
2. 研究結果表的列數，是否等於原論文檢驗的假說或路徑數；速覽的成立數是否和表格一致。
3. 原論文的構念有沒有被改名成別的構念；「對應本研究構念」有沒有誇大兩者的相似程度。
4. 作者自述的缺口、限制、未來研究，在標示的頁碼找不找得到。
5. 「可引用的發現」有沒有寫得比原研究設計更強（例如橫斷面研究寫成「影響」「導致」）。
6. 筆記裡有沒有出現不屬於原論文的假說編號。
7. 「研究背景」「我的批判」「它做到的與沒做到的」各抽 2 句：有 PDF 依據，或明確是筆記作者的判斷？
最後列出你建議修改的地方，由我決定要不要改。
```

**CLI 版**：

```text
請核對 03_文獻筆記/⟨citekey⟩.md，對照 _pdf/⟨citekey⟩.txt（PDF 轉出的文字，「===== PDF p. N =====」是分頁標記）。只做核對，不要修改任何檔案。
先讀 00_總覽/文獻筆記填寫規則.md。逐條檢查，每條回報「通過／不通過」，不通過要寫出筆記原句、PDF 原句和頁碼。下面用的是實證型筆記的章節名稱；理論型、方法型就找對應的那一節，沒有對應的項目回報「不適用」。
1. 抽 10 個數字回文字檔對，要一字不差（數字少於 10 個就全查）。
2. 研究結果表的列數，是否等於原論文檢驗的假說或路徑數；速覽的成立數是否和表格一致。
3. 原論文的構念有沒有被改名；「對應本研究構念」有沒有誇大相似程度。
4. 作者自述的缺口、限制、未來研究，在標示的頁碼找不找得到。
5. 「可引用的發現」有沒有寫得比原研究設計更強。
6. 筆記裡有沒有不屬於原論文的假說編號。
7. frontmatter 的「連結的概念筆記」是否都指向 01_理論/、02_變數/、06_方法/ 裡實際存在的檔案，並符合規則第四節的連結條件。
8. 「研究背景」「我的批判」「它做到的與沒做到的」各抽 2 句：有 PDF 依據，或明確是筆記作者的判斷？
最後列出建議修改的地方，由我決定要不要改。
```

**AI 回來後你要檢查**：不通過的項目自己回 PDF 看一次再改（核對的 AI 也會看錯）。全部處理完，把筆記的 `verified` 填上今天日期。


### 6.4 收料進構念卡

**什麼時候用**：某個構念累積了幾張論文卡，要開始整理第二章那一節。

**網頁版**：

```text
下面貼的是幾份文獻筆記，都跟「⟨構念名稱⟩」有關。請整理成構念卡的草稿：
- 定義差異：各篇怎麼定義這個構念，定義有沒有差異。這段之後我會放進構念卡第 1 節「定義與構念邊界」。
- 現有共識：多篇一致的發現。
- 爭議與缺口：發現互相矛盾、或還沒人檢驗的地方。
規則：
- 每句句尾標出來自哪份筆記，格式 [[citekey]]。筆記裡沒有的內容不寫，不要用你的背景知識補。
- 用詞照各篇的研究設計：橫斷面研究寫「預測」「相關」，不寫「影響」「導致」。
- 不要寫「本研究的切入點」，那格由我自己寫。
⟨貼上筆記⟩
```

**CLI 版**：

```text
請整理 02_變數/⟨構念卡檔名⟩.md 的「2. 文獻回顧草稿區」。
```

### 6.5 推演卡健檢

**什麼時候用**：寫完一張推演卡，或要去跟老師討論假說之前。

**網頁版**：

```text
下面是一張假說推演卡，以及它引用的文獻筆記。請檢查：
1. 理論推導有沒有跳步：從理論到這兩個構念的關係，中間少了哪一步？
2. 支持性實證的證據型態：每篇屬於直接實證（同構念、相近情境）、類比實證（鄰近構念或不同情境）還是只是理論推導？整張卡的證據型態該填哪一種？
3. 卡片裡描述的發現，用詞有沒有比原研究設計更強。
4. 邊界條件：還有哪些情況這條假說可能不成立？只提有文獻依據的，並標出依據。
只列問題和建議，不要改寫整張卡。
⟨貼上推演卡和相關筆記⟩
```

**CLI 版**：

```text
請健檢 05_假設推演/⟨推演卡檔名⟩.md。先讀它引用的每一張論文卡和構念卡，再檢查：
1. 理論推導有沒有跳步：從理論到這兩個構念的關係，中間少了哪一步？
2. 每篇支持性實證屬於直接實證、類比實證還是理論推導；frontmatter 的 evidence_type 填得對不對。
3. 卡片裡描述的發現，用詞有沒有比原論文卡記錄的研究設計更強。
4. 卡片引用的每個發現，在對應的論文卡裡找不找得到。
只列問題和建議，不要修改任何檔案。
```

**AI 回來後你要檢查**：「跳步」那一項自己想一次能不能補；補不起來的，帶去問老師。
