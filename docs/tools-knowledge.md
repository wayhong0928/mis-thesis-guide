# 文獻管理與知識庫

> 這一頁處理一件研究所第一個月就該解決、但幾乎沒有人教的事：**你的檔案、文獻、筆記要放在哪裡，兩年後還找得到。**
>
> 工具本身不會讓你變成好的研究者，但**沒有系統會讓你在寫作階段付出巨大的代價**。最典型的情況是第五章寫到一半，想不起某個關鍵論點出自哪一篇。

---

## 一、先分清楚三種東西

很多人的痛苦來自把三件事塞進同一個工具：

| 類型 | 內容 | 特性 | 適合的工具 |
|---|---|---|---|
| **文獻庫** | PDF、書目資料（作者、年份、期刊、DOI） | 結構化、要能一鍵產生引用格式 | 文獻管理軟體（Zotero 等） |
| **知識庫** | 你自己寫的筆記、概念、論證、想法之間的連結 | 非結構化、要能長期演化 | 筆記軟體（Obsidian 等） |
| **產出檔** | 論文草稿、投影片、資料檔、程式碼 | 有版本、有截止日 | 文書軟體＋雲端硬碟＋（程式的話）Git |

!!! tip "最小可行架構"
    **一個文獻管理軟體 ＋ 一個筆記軟體 ＋ 一個雲端硬碟。** 三個就夠了。工具愈多，同步與遷移的成本愈高。研究所兩年最不該花時間的地方，就是不斷更換工具。

---

## 二、文獻管理軟體

核心功能其實只有四項，其他都是加分：

1. **抓取書目**：在瀏覽器上按一下就把論文的作者、年份、期刊、DOI 與 PDF 存進資料庫。
2. **產生引用**：在文書軟體裡插入引用，並自動生成參考文獻清單，支援 APA 7 等格式。
3. **全文搜尋**：能搜尋 PDF 內文與自己的註記。
4. **匯出與遷移**：能匯出成 BibTeX／RIS，換工具時不會被綁死。

| 工具 | 授權 | 特點 | 要注意的地方 | 官方網站 |
|---|---|---|---|---|
| **Zotero** | 開放原始碼、免費 | 社群外掛生態最完整；資料格式開放，最不容易被綁架 | 雲端同步空間免費額度有限，可自行接 WebDAV 或自架儲存 | <https://www.zotero.org/> |
| **Mendeley** | 免費（Elsevier） | 內建 PDF 註記與閱讀器 | 屬於出版社生態系，功能與政策由該公司決定 | <https://www.mendeley.com/> |
| **EndNote** | 商業授權 | 台灣許多大學圖書館有校園授權；期刊投稿的樣式檔最齊全 | 授權綁學校，畢業後可能失效；先確認你的學校有沒有 | <https://endnote.com/> |
| **Paperpile** | 訂閱制 | 與 Google Docs 整合最順 | 需付費；以雲端為中心 | <https://paperpile.com/> |
| **JabRef** | 開放原始碼、免費 | 純 BibTeX 取向，適合寫 LaTeX 的人 | 介面偏技術取向 | <https://www.jabref.org/> |

!!! note "先去問圖書館"
    幾乎每一所大學的圖書館都有文獻管理軟體的**校園授權與教學講座**，而且通常會教到「怎麼接你們系所的論文格式」。這是最快的起步方式，也是最少人利用的資源。**在自己摸索之前，先花二十分鐘看看圖書館的資源頁。**

### 2.1 不管用哪一套，這五件事一定要做

- [ ] **開一個資料庫就好**，用資料夾／標籤分主題，不要開很多個資料庫。
- [ ] **書目資料抓進來後手動校對一次**：作者姓名順序、期刊名稱縮寫、年份、卷期頁碼。自動抓的資料錯誤率不低，錯了會一路錯到參考文獻清單。
- [ ] **DOI 一定要填**。它是唯一穩定的識別碼，換工具、查全文、給指導教授看都靠它；Zotero 使用者也可以反過來直接拿 DOI 匯入新文獻，做法見下方 2.3.5。
- [ ] **設定備份**：資料庫本體＋PDF 目錄，一起放進雲端硬碟或定期匯出。
- [ ] **確認匯出得出去**：第一週就試著匯出一次 BibTeX，確保你隨時可以離開這個工具；Zotero 使用者建議先裝好下方 2.3.4 的 Better BibTeX 外掛再做這件事，匯出的 citekey 才會穩定。

### 2.2 引用格式的鐵則

**不要手打參考文獻。** 手打的清單一定會有格式不一致，而口試委員與期刊編輯一定看得出來。

但也**不要完全信任自動產生的結果**：交稿前一定要人工核對一次，重點是中文文獻的排序、期刊名稱的斜體、以及 APA 7 對於超過 20 位作者、DOI 呈現方式的規則。格式細節見[學術中文寫作紀律](style.md)。

### 2.3 Zotero 實戰教學：從抓文獻到寫進 Word

上面兩節談的是「選哪套工具」與「引用格式的鐵則」。如果你選的是 Zotero（本頁比較表中社群外掛最完整、資料最不容易被綁架的那一套），這一節把從抓文獻到寫進 Word 的完整流程走一遍，寫給第一次用 Zotero 的人看。操作細節已對照 [Zotero 官方文件](https://www.zotero.org/support/)與 [Better BibTeX 官方文件](https://retorque.re/zotero-better-bibtex/)查證，選單名稱以官方原文為準，畫面可能隨版本略有差異。

#### 2.3.1 第一步：登入學校圖書館帳戶，否則多數全文抓不到

沒有校園連線資格時，Zotero Connector 常常只擷取得到書目資料，抓不到 PDF 全文——因為期刊網站看你的 IP 不是校園網段，直接判定你沒有訂閱權限。校外取得全文權限通常有兩種管道，操作前先選一種完成登入：

- **VPN 全連線**：接上學校的 VPN 之後，你的網路流量對期刊網站來說就等同校園 IP，效果最完整。
- **圖書館網頁代理（proxy，例如 EZproxy 一類系統）**：從圖書館入口網站的資料庫連結點進去，會先跳轉到一個登入頁，輸入學校帳密後才轉進期刊網站。

Zotero Connector 對代理有自動偵測機制：偵測到你正透過機構代理造訪某個網站時，會跳出提示問你要不要記住這個代理設定，同意之後之後造訪同一網域會自動幫你轉走代理登入流程（[官方說明](https://www.zotero.org/support/connector_preferences)）。

!!! note "DOI 匯入自動找全文，VPN 比網頁代理更可靠"
    用 Zotero 的「以識別碼新增項目」或「Find Available PDF」功能透過 DOI 自動找全文時，如果你是 VPN 連線，能抓到有訂閱權限的全文；如果是網頁代理登入，這個自動抓取功能只保證抓得到公開取用（open access）的全文，有訂閱權限但非公開的 PDF 抓不到——這時候還是要用 Zotero Connector 直接在已登入代理的期刊頁面上手動存，才抓得到全文。兩種校外連線方式都能用，差別只在「自動找全文」這個功能的涵蓋範圍。

#### 2.3.2 三個主要下載管道

| 管道 | 適合找什麼 | 要注意的地方 |
|---|---|---|
| **華藝線上圖書館（airiti）** | 中文文獻主力，多數台灣期刊、學位論文收錄在此 | 需要校園連線或圖書館代理登入才能下載全文 PDF |
| **ResearchGate** | 作者自行上傳的版本 | 常是投稿前或校對前的版本（preprint／author manuscript），內容可能與正式出版稍有出入，引用前對一下期刊正式版的頁碼與措辭 |
| **期刊官方網站** | 正式出版版本（Version of Record） | 從文獻的 DOI 連結直接進期刊頁面下載，排版與頁碼是最終定案，論文裡要標頁碼引用時以這份為準 |

三個管道下載下來的都存成 PDF，接下來的動作交給 Zotero Connector 處理。

#### 2.3.3 用 Zotero Connector 一鍵擷取、分類、存 PDF

1. 先在瀏覽器裝好 [Zotero Connector](https://www.zotero.org/support/connector) 外掛（Zotero 官網下載頁會依你的瀏覽器提供對應版本）。
2. 開著 Zotero 桌面應用程式，在左側選好要存進哪個 collection。
3. 在期刊頁面或華藝頁面上點瀏覽器工具列的 Zotero 圖示，官方文件的說法是「點一下按鈕就會把目前開啟的網站存進你的 Zotero 資料庫」——書目資料與該頁面能抓到的 PDF 附件會一起存進你剛剛選好的 collection。
4. 事後想搬到別的 collection，直接在 Zotero 裡拖曳項目即可，不必重新擷取。

#### 2.3.4 一定要裝：Better BibTeX 外掛

**Better BibTeX（BBT）**是 Zotero 的延伸外掛，官方定位是「改善 BibTeX／biber 匯出功能」，核心價值有兩個：

- 產生**穩定、可預期的 citation key**（例如 `chen2024perceived`）。Zotero 原生也會給每筆文獻一個 key，但官方文件明講「Zotero 的 key 不一定適合 bibtex/biber 使用」；BBT 會依你設定的公式重新產生一套一致的 key。
- 資料庫更新時**自動即時匯出**一份 `.bib`，讓 LaTeX／Overleaf／Pandoc 之類的工具隨時讀到最新書目，不必每次手動匯出。

安裝步驟（[官方安裝說明](https://retorque.re/zotero-better-bibtex/installation/)）：

1. 到 [Better BibTeX 的 GitHub Releases 頁](https://github.com/retorquere/zotero-better-bibtex/releases/latest)下載最新版的 `.xpi` 檔（用 Firefox 開啟該頁時要用右鍵另存,直接點擊會被瀏覽器攔截）。
2. 打開 Zotero，工具列選「工具（Tools）→ 外掛程式（Plugins）」。
3. 點外掛程式視窗右上角的齒輪圖示，選「從檔案安裝外掛程式（Install Plugin From File）」。
4. 選剛剛下載的 `.xpi` 檔即完成安裝，之後 BBT 會自動更新版本。

#### 2.3.5 也可以直接打 DOI／ISBN 匯入

不想靠瀏覽器擷取時，Zotero 工具列有個「**以識別碼新增項目（Add Item by Identifier）**」按鈕，點下去、貼上識別碼、按 Enter 就會自動查回書目資料。支援的識別碼包括 DOI、ISBN、PubMed ID、arXiv ID、ADS Bibcode；要一次匯入多筆，識別碼之間用空格、逗號或換行分隔即可（[官方說明](https://www.zotero.org/support/adding_items_to_zotero)）。

!!! warning "這樣匯入通常不會附全文 PDF"
    「以識別碼新增項目」查到的是書目資料庫（CrossRef、WorldCat、arXiv 等）裡的中繼資料，不是期刊頁面本身，所以官方文件並沒有把它跟自動下載 PDF 綁在一起——相對地，透過 Zotero Connector 直接在期刊頁面上擷取，通常會一併抓到 PDF。用 DOI 打進書目之後，PDF 全文多半還是要回到 2.3.1／2.3.2 兩節描述的管道自己下載，再手動拖進該筆文獻底下當附件。

#### 2.3.6 日期格式會決定你的 citation key 亂不亂

這是 Better BibTeX 使用者最常踩、也最不容易自己查出原因的雷：日期欄位亂填，citekey 會跟著亂。原理分三層：

1. **Zotero 的日期欄位不是純文字，而是會被解析（parse）成結構化的年／月／日。** 這個解析器認得的日期寫法，綁定在你目前 Zotero 介面設定的語言（locale）上——不同語言的月份名稱、日期順序寫法不一樣，例如英文介面認得 `January`、`5/1/2024` 這類英文慣例的寫法，中文介面才認得「年」「月」「日」這種寫法。
2. **介面設成英文卻打中文格式的日期（例如「2024年5月1日」），這串文字裡的「年」「月」「日」不在英文解析器認得的樣式清單裡**，Zotero 解析不出結構化的年份，這個欄位就退化成一段沒有結構的純文字——這筆文獻的後設資料裡，沒有一個乾淨可用的「年」。
3. **Better BibTeX 的 citekey 公式裡，`year` 這個函式抓的是「出版年份」這個已經解析好的值**，不是它自己重新去猜你輸入的原始字串。官方文件所舉的預設公式範例是 `auth.lower + shorttitle(3,3) + year`（作者姓氏＋短標題＋年份）。上一步解析失敗，這裡年份那一段就是空的：好幾筆作者、標題相近但年份缺失的文獻，就會擠出幾乎一樣的 key。Better BibTeX 偵測到 key 重複時會自動加字尾（a、b、c……）區分，你看到的結果就是 citekey 缺一截年份、或被加上莫名其妙的字尾——這就是「亂掉」的真正樣子，不是 Zotero 故障，是那筆日期資料一開始就沒被解析成功。

**修法**：日期欄位一律填 `YYYY-MM-DD`（例如 `2024-05-01`），只知道年份就只填 `YYYY`（例如 `2024`）。這兩種寫法都是純數字、順序固定，不吃任何語言的月份名稱或日期順序慣例，在哪種介面語言下都會被正確辨識成合法日期——這也是 Zotero 論壇與官方說明一致建議的填法。改完日期後，回 Zotero 選取受影響的項目，右鍵→Better BibTeX→**Refresh BibTeX Key**，重新產生 citekey。

!!! danger "citekey 重新產生之後，已經插進 Word 裡的舊引用不會自動跟著換"
    如果亂掉的 citekey 已經拿去 Word 裡插入引用，Refresh 之後兩邊會對不起來，變成斷link。**最好在正式開始大量插入引用之前，就先把整批文獻的日期欄位處理乾淨**，越晚發現，要重新核對的引用就越多。

#### 2.3.7 怎麼引用到 Word

Zotero 安裝時通常會自動裝好 Word 外掛（[官方安裝說明](https://www.zotero.org/support/word_processor_plugin_installation)：「首次啟動 Zotero 時，應該會自動幫每個支援的文書處理器裝好外掛」）。裝好之後 Word 功能區會多一個「Zotero」分頁，常用的三個按鈕（[官方使用說明](https://www.zotero.org/support/word_processor_plugin_usage)）：

- **Add/Edit Citation（插入／編輯引用）**：第一次使用會先跳出 Document Preferences 讓你選整份文件的引用格式（例如 APA 7th Edition）。之後每次要插入引用，點這個按鈕、打作者姓氏或標題關鍵字，從搜尋結果選文獻、按 Enter 即插入。
- **Add/Edit Bibliography（插入／編輯書目）**：在文件某處插入參考文獻清單；之後每插入一筆新引用，這份清單會自動更新，不必手動排序或增刪。
- **Document Preferences（文件偏好設定）**：隨時可以回來換整份文件的引用格式，換了之後所有已插入的引用與書目會一次重新格式化，不用逐筆手動改。

!!! warning "定稿前才做 Unlink Citations，而且不可逆"
    Word 裡的 Zotero 引用其實是內嵌的欄位代碼（field code），不是純文字，所以千萬不要用手直接改引用的文字，要改就回到 Add/Edit Citation 重新選。真的要投稿或口試繳交、確定不會再改文獻時，才用 Zotero 分頁裡的「**Unlink Citations**」把整份文件的引用與書目轉成純文字——這個動作官方文件明講不可逆，做之前先另存一份備份（[官方說明](https://www.zotero.org/support/kb/unlinking_citations)）。

## 三、筆記與知識庫軟體

文獻管理軟體存的是「別人寫的東西」，筆記軟體存的是「你想的東西」。後者才是兩年後真正屬於你的資產。

| 工具 | 資料存在哪 | 特點 | 適合誰 | 官方網站 |
|---|---|---|---|---|
| **Obsidian** | 本機的 Markdown 檔 | 雙向連結、圖譜視圖、外掛生態豐富；檔案就是純文字，永遠可讀 | 想要長期保存、不想被平台綁住的人 | <https://obsidian.md/> |
| **Notion** | 雲端資料庫 | 資料庫視圖（表格／看板／日曆）強，適合管理進度與清單；協作方便 | 需要跟人共用、需要管理待辦與進度的人 | <https://www.notion.com/> |
| **Heptabase** | 雲端＋本機 | 白板式思考，可以把卡片攤在畫布上拉關係 | 在「整理思緒」階段卡住、需要視覺化的人 | <https://heptabase.com/> |
| **Logseq** | 本機的 Markdown／Org 檔 | 大綱（outliner）取向，適合每日流水帳式記錄 | 習慣用條列思考的人 | <https://logseq.com/> |
| **Zettlr** | 本機的 Markdown 檔 | 專為學術寫作設計，內建引用與匯出 | 想在同一個工具裡寫完論文的人 | <https://www.zettlr.com/> |

!!! warning "選工具的唯一實用判準：資料能不能拿得出來"
    研究所兩年、加上之後可能繼續讀博或工作，你的筆記要活十年以上。判準只有一個：**這個工具倒了，我的東西還在不在？**
    存成本機純文字（Markdown）的工具在這一點上有結構性的優勢；雲端型工具則要先確認匯出功能實際跑一次的結果長什麼樣（很多工具「可以匯出」，但匯出的東西連結全斷）。

### 3.1 一篇論文一則，一個概念也一則

多數人只做前者，這是知識庫長不出來的主因。

- **文獻筆記**：一篇論文一則。它處理的是「這篇說了什麼」。
- **概念筆記**：一個概念一則。例如「知覺有用性」「共同方法變異」「區別效度」各一則，裡面連結到所有提到它的文獻筆記。

**只有概念筆記會累積。** 文獻筆記是線性增加的（讀十篇就有十則），概念筆記是**收斂**的（讀十篇之後，「區別效度」那一則變得更完整）。寫第二章時，你可以先打開概念筆記，查看定義的演變、各家爭議與自己的判斷，再回到原文組織段落。

這正是[文獻回顧與批判性思考](literature.md)裡「概念中心（concept-centric）」寫法在工具層次的落實。

- Webster, J., & Watson, R. T. (2002). Analyzing the Past to Prepare for the Future: Writing a Literature Review. *MIS Quarterly*, 26(2), xiii–xxiii. <https://aisel.aisnet.org/misq/vol26/iss2/3/>

### 3.2 建立範本，不要每次重想欄位

範本的作用不是好看，而是**提醒你反覆檢查同一組問題**。欄位空著，可能代表那件事還沒想清楚。下一節提供五種範本。

---

## 四、五種筆記範本

一套夠用的知識庫由五種筆記構成。它們的分工是：

| 筆記類型 | 一則對應什麼 | 回答的問題 | 誰引用誰 |
|---|---|---|---|
| **文獻筆記** | 一篇論文 | 這篇說了什麼、有什麼毛病 | 被下面四種引用 |
| **變數／現象筆記** | 一個構念 | 這個東西怎麼定義、怎麼量 | 引用文獻筆記 |
| **理論筆記** | 一個理論 | 它預測什麼、在哪失效 | 引用文獻筆記 |
| **方法筆記** | 一種方法或指標 | 怎麼做、擋掉什麼偏誤、門檻多少 | 引用文獻筆記 |
| **命題筆記** | 一條假說 | 為什麼 A 會影響 B | 引用上面三種 |

!!! tip "為什麼要分這麼細"
    因為**論文的每一節都對應其中一種**：第二章來自變數與理論筆記，第三章來自方法筆記，假說推導來自命題筆記。
    分開寫的好處是，你寫論文時是在**組裝**，而不是從零開始寫。

下面五份範本可複製到 Obsidian、Notion 或其他 Markdown 工具，適合做個人研究筆記的起始架構，不是所有學科、方法或合作團隊都必須採用的標準。請依研究問題、資料型態、倫理要求與團隊分工調整欄位；空著的欄位可以提醒尚待釐清之處。

### 4.1 文獻筆記

```markdown
---
type: paper
citekey:
authors:
year:
journal:
tier:            # 期刊層級，例如 SSCI Q1 / AIS 頂級期刊 / 一般會議
method:          # Survey / Experiment / Case / DSR / Mixed
context:         # 研究對象與任務情境
---
# 論文標題

**[一句話結論]**：

## 1. 研究模型與理論
- **依變數（Y）**：
- **自變數（X）**：
- **中介／調節（M／W）**：
- **核心理論**：
- **模型推演邏輯**：為什麼挑這些變數？箭頭之間的因果基於什麼理論？
- **關聯**：[[變數-…]]、[[理論-…]]

## 2. 研究動機與缺口
- **實務重要性**：
- **學術有趣點**：它挑戰了什麼？解決了哪個矛盾？
- **核心研究問題**：

## 3. 方法與嚴謹度
- **研究設計與任務情境**：
- **操作型定義與量表來源**：主觀自評還是客觀表現？
- **操弄檢核與偏誤防禦**：怎麼確認受試者真的感受到操弄？CMV 怎麼防？
- **核心數值**：R²、關鍵路徑係數與 p 值、效果量

## 4. 批判（惡魔的代言人）
- **邏輯漏洞與限制**：樣本？橫斷面？測量？
- **替代解釋**：有沒有未測量的變數也能解釋這個結果？

## 5. 我的用處
- **可引用的句型**：「⋯⋯」(p. XX)
- **對我的研究的啟發**：我要在第幾章用它？借它的量表還是避開它的弱點？
```

**最後兩節是價值所在。** 前四節 AI 幫得上忙；「批判」與「我的用處」只有你寫得出來，那是你的問題意識在運作。

### 4.2 變數／現象筆記

```markdown
---
type: variable
aliases: [同義詞、英文縮寫]
status: 🌱      # 🌱 剛建立 / 🌿 充實中 / 🌳 可直接寫進論文
---
# 變數 - 名稱

**[一句話速記]**：用最直白的話描述這個構念的本質。

## 1. 定義與構念邊界
- **學術定義**：（引用權威文獻的正式定義）
- **易混淆的鄰居**：（跟哪個概念常被搞混？差別在哪？）

## 2. 文獻回顧草稿區
*（用正式學術口吻寫，未來直接搬進第二章）*
- **現有共識**：目前學界普遍認為⋯⋯（Author, Year）
- **爭議與缺口**：然而在 ⟨某個面向⟩ 上，文獻存在分歧。一派主張⋯⋯（A, Year）；
  另一派卻發現⋯⋯（B, Year）。此矛盾可能源自過去研究忽略了 ⟨某個情境或中介變數⟩。
- **本研究的切入點**：為填補上述缺口，本研究將此構念置於 ⟨你的情境／理論⟩ 下重新檢視⋯⋯

## 3. 操作化與測量防禦
- **測量典範**：客觀表現型 vs. 主觀自評
- **構面屬性**：單一構面還是多構面？
- **具體題項範例**：
- **偏誤防禦**：怎麼降低共同方法變異與社會期許偏誤？

## 4. 核心文獻
```

!!! tip "第 2 節是這份範本的重點"
    **「共識 → 爭議 → 我的切入點」這三段，就是第二章每一小節的骨架。**
    平常讀文獻時一句一句補進去，寫第二章時直接搬，這是把閱讀時間轉換成寫作進度最直接的方式。三層結構的完整說明見[文獻回顧與批判性思考](literature.md)第五節。

### 4.3 理論筆記

```markdown
---
type: theory
aliases: [英文縮寫]
status: 🌱
---
# 理論 - 名稱

**[一句話速記]**：這個理論主要用來解釋或預測什麼？

## 1. 核心預測與機制
- **它最終在解釋什麼現象**（Outcome First）：
- **運作機制**：拆解理論的齒輪（例如：雙路徑處理、資源消耗）

## 2. 關鍵構念
- **驅動變數**：[[變數-…]]
- **中介／情境變數**：[[變數-…]]

## 3. 邊界與競爭理論
- **競爭理論**：這個現象還能用什麼理論解釋？為什麼本理論更適合我的情境？
- **失效條件**：這個理論在什麼情況下不成立？

## 4. 在我的研究裡怎麼映射
- 理論中的 ⟨某個構念⟩ ＝ 本研究的 [[變數-…]]
- **理論突破點**：我如何擴充或修正它在新情境下的適用性？

## 5. 核心文獻
```

**第 3 節的「競爭理論」是口試題。** 「你為什麼用這個理論不用那個？」答不出來，整章的正當性就垮了。相關判準見[理論的構成與評估](theory-building.md)。

### 4.4 方法筆記

```markdown
---
type: methodology
aliases: [英文縮寫]
status: 🌱
---
# 方法 - 名稱

**[一句話速記]**：這個方法的本質是什麼？用來迴避什麼地雷？

## 1. 定義與操作程序
- **標準程序**：第一步⋯⋯第二步⋯⋯
- **資料蒐集與編碼**：怎麼把原始現象標準化？編碼簿怎麼規劃？

## 2. 它解決的痛點與變異數控制
- **防禦對象**：它摧毀了哪一種偏誤？
- **最大化實驗變異**：怎麼讓自變數的操弄差異夠大？
- **最小化誤差變異**：怎麼降低隨機誤差？
- **控制干擾變數**：怎麼鎖住那些會影響 Y 但不是 X 的東西？

## 3. 在我的研究裡的實作與門檻
- **實作細節**：
- **檢核指標與閾值**：（例如：區別效度 HTMT < 0.85、共線性 VIF < 3；**門檻依領域與期刊而異，引用前查最新來源**）

## 4. 限制與備胎方案
- **潛在風險**：實作上最容易失敗的地方？
- **備胎方案**：如果操弄失敗或樣本不足，分析策略可以怎麼降階？

## 5. 核心文獻
```

第 2 節那三個問題（最大化、最小化、控制）是實驗設計的通用檢核，也適用於問卷設計；細節見[實驗法](method-experiment.md)與[問卷調查法](method-survey.md)。

### 4.5 命題／假說推演筆記

```markdown
---
type: claim
status: 🌱
---
# 假設推演：[[變數-A]] 如何影響 [[變數-B]]

## 1. 理論推導邏輯
*（用底層理論解釋「為什麼」A 與 B 之間預期有特定關係；這一段是假說的核心）*
根據 [[理論-…]]，當個體具備較高的 [[變數-A]] 時，會啟動 ⟨某個機制⟩，
進而導致 [[變數-B]] 增加／減少。

## 2. 支持性實證
- Author (Year) 在 ⟨某情境⟩ 下發現 A 對 B 有正向影響，效果量為⋯⋯
- Author (Year) 的實驗證實⋯⋯

## 3. 邊界條件與潛在干擾
這個假設在什麼情況下可能不成立？（例如：在 ⟨某種壓力條件⟩ 下，
A 對 B 的影響可能被削弱，因為⋯⋯）

## 4. 假設草稿
**H1**：在 ⟨情境⟩ 下，⟨變數 A⟩ 會顯著正向／負向影響 ⟨變數 B⟩。
```

!!! danger "沒有第 1 節就只是相關性的堆疊"
    「文獻指出 A 與 B 有正相關，因此提出 H1。」這種寫法在口試時通常仍須補充機制與邊界條件。
    **每一條假說都欠一段「為什麼」，而那段「為什麼」必須來自某個理論機制。** 詳見[理論的構成與評估](theory-building.md)第六節。

## 五、把兩邊接起來

文獻庫與知識庫要能互相跳轉，否則你會在兩個系統之間重複輸入。常見的串接方式：

| 做法 | 怎麼運作 |
|---|---|
| **用引用鍵當共同語言** | 在文獻管理軟體裡固定一套引用鍵（如 `davis1989perceived`），筆記檔名與標題都用同一組鍵，兩邊靠這個對上。Zotero 使用者要注意這個鍵怎麼被產生、什麼情況下會亂掉，見下方 2.3.6。 |
| **在筆記裡放回連結** | 每則文獻筆記開頭放一個可以直接開啟該筆文獻的連結（多數工具支援自訂協定連結）。 |
| **匯出 BibTeX 給筆記工具讀** | 定期從文獻管理軟體匯出一份 `.bib`，讓筆記工具的外掛讀取，寫作時可直接插入引用。Zotero 使用者可用 Better BibTeX（見 2.3.4）自動即時匯出，不必每次手動操作。 |
| **PDF 註記匯入筆記** | 在 PDF 上畫的重點與註記可以匯出成 Markdown，貼進文獻筆記的「可引用句」欄位。 |

!!! tip "不要一開始就追求全自動"
    串接是有維護成本的。第一個月請先做到「**每讀完一篇就留下一則筆記**」這件事本身。自動化留到你確定自己的流程穩定之後再做。

!!! warning "書目只保留一個主要來源"
    若從 BibTeX 或 `.bib` 檔切換到 Zotero，不要同時手動維護兩套書目。指定一套作為唯一來源，其他格式只由它匯出，才能避免作者、年份與題名不一致。Zotero 在 Word 裡插入引用與書目的完整操作步驟見上方 2.3.7；把 Markdown 章節組裝成 Word 的流程，見[論文架構與各章寫作要領](writing.md)第 2.2 節。

## 六、檔案與備份

這一節看起來很無聊，但**每年都有人因為這一節出事**。

### 6.1 資料夾結構

一套夠用的結構：

```
碩士論文/
├── 00_行政/         系所表單、時程、口試相關文件
├── 01_文獻/         PDF（若文獻管理軟體已代管，這裡只放例外）
├── 02_筆記/         知識庫（若用 Obsidian，這就是 vault）
├── 03_資料/
│   ├── raw/         原始資料，唯讀，永遠不覆寫
│   ├── clean/       清理後的資料
│   └── scripts/     處理與分析程式
├── 04_草稿/         論文各章草稿
├── 05_投影片/       進度報告、計畫書、口試簡報
└── 06_產出/         最終版 PDF、附錄
```

**`raw/` 唯讀是鐵律。** 所有清理都用程式從 `raw/` 讀進來、寫到 `clean/`，永遠不要就地修改原始資料。這樣任何一步做錯都可以重跑，而且第三章可以誠實地寫出資料處理流程。

### 6.2 檔名慣例

```
2026-03-14_第二章_v03_指導教授回饋後.docx
```

- **日期用 `YYYY-MM-DD`**（可以正確排序）
- **不要用「最終版」「真的最終版」「final_final」**
- **改動大的存新檔**，不要覆蓋；硬碟很便宜，重寫一章很貴

### 6.3 三二一備份原則

- **三份**副本
- 存在**兩種**不同的媒介（例如本機硬碟＋雲端）
- 其中**一份**在異地（雲端硬碟即可）

!!! danger "只放雲端不算備份"
    同步（sync）不是備份（backup）。你在本機誤刪、誤覆寫的檔案，會被同步到雲端一起消失。所以要**額外**保留一份不會被自動同步覆蓋的版本，例如定期壓縮完整備份，存到另一個雲端帳號或外接硬碟。

### 6.4 個資與敏感資料要分開放

如果你的研究會蒐集問卷、訪談錄音或任何可以識別到人的資料：

- **原始個資與研究資料分開存放**，用代號串接（如 P01、P02）。
- **對應表另外加密保存**，不要跟資料放在同一個資料夾，更不要放進 Git 版控或公開的雲端資料夾。
- 訪談錄音檔轉譯完成後，依 IRB 核准的保存期限處理。
- 詳見[學術倫理與 AI 揭露](ethics.md)。

## 八、本頁重點回顧

- 分清楚**文獻庫／知識庫／產出檔**，不要塞進同一個工具。
- 選工具的唯一實用判準是**資料拿不拿得出來**，先試一次匯出再投入。
- 文獻筆記的價值在「**對我的用處**」與「**批判**」兩個欄位，那是 AI 寫不出來的部分。
- **概念筆記**才是讓第二章寫得動的東西：文獻筆記線性增加，概念筆記會收斂。
- 五種筆記各對應論文的一個部位：文獻／變數／理論／方法／命題。分開寫，寫論文時就是**組裝**而不是重寫。
- 變數筆記的「共識 → 爭議 → 我的切入點」三段，就是第二章每一小節的骨架。
- `raw/` 資料唯讀，所有處理都靠程式；檔名用日期，不要用「最終版」。
- **同步不是備份**；個資與研究資料分開放，對應表另外加密。
