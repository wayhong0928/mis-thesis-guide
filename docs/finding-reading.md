# 怎麼找 paper、怎麼讀 paper、怎麼選題目

> 這三題是研究所前半年被問最多、也最少被正式教的問題。網路上的答案多半是零散的心得，這一頁把它整理成可以照著做的流程，並附上可查證的公開資源。
>
> 相關頁面：[文獻回顧與批判性思考](literature.md)（怎麼把讀到的東西寫成第二章）、[文獻管理與知識庫](tools-knowledge.md)（讀完的東西放哪裡）、[研究問題、假說與研究架構](problem-design.md)（題目定了之後怎麼變成假說）。

---

## 一、先搞懂三件事的順序

多數人卡住，是因為把順序想反了。正確的順序是**螺旋的，不是直線的**：

```
粗略方向（一個領域、一個現象）
   ↓
找 20–30 篇 → 快速掃過 → 挑出 5–8 篇認真讀
   ↓
發現「大家都在吵什麼」「哪裡還沒被回答」
   ↓
把方向收窄一階 → 再找、再讀
   ↓（重複 2–3 輪）
一個具體到可以被回答的題目
```

!!! danger "兩個最常見的錯誤起手式"
    **① 先想題目再找文獻。** 憑空想出來的題目，九成不是已經被做過，就是根本不成立。文獻是題目的來源，不是題目的驗證工具。
    **② 想「先讀完所有相關文獻再說」。** 讀不完的。文獻的邊界要靠題目來劃，而題目要靠讀文獻來收斂，因此必須螺旋進行。

## 二、怎麼找 paper

### 2.1 先分清楚「找什麼」

不同階段要找的東西不一樣，用同一種找法一定會卡：

| 階段 | 你要找的 | 找法 |
|---|---|---|
| 完全不懂這個領域 | **回顧型論文**（review／survey／SLR）、中文碩博士論文 | 關鍵字加上 `review`、`systematic literature review`、`a survey of` |
| 抓領域的骨架 | 該領域的**高被引經典** | 依被引用次數排序，看被引超過 500 次的那幾篇 |
| 找研究缺口 | **近三年的頂級期刊論文** | 限定年份 + 限定期刊 |
| 補特定方法 | **方法論論文** | 用方法名稱當關鍵字，不要用主題 |
| 確認沒人做過 | **最新、最像你題目的那幾篇** | 用你題目的精確詞組加引號搜尋 |

!!! tip "碩博士論文的正確用法"
    中文碩博士論文**不能當作理論依據來引用**（那是學位論文，不是經過同儕審查的期刊論文），但它有兩個無可取代的用途：
    ① 它的第二章通常把該主題的英文文獻整理過一遍，**可拿它當地圖，再去讀它引用的原文**；
    ② 它的參考文獻清單是現成的檢索起點。
    看它整理的內容，然後回去讀原文；不要引用它的整理。

### 2.2 從哪裡找

| 管道 | 適合什麼 | 連結 |
|---|---|---|
| **Google Scholar** | 覆蓋最廣的起點，被引用次數與「被引用」反查最好用 | <https://scholar.google.com/> |
| **Semantic Scholar** | 語意檢索、自動摘要、引文脈絡（會告訴你後人是正面還是反面引用） | <https://www.semanticscholar.org/> |
| **AIS eLibrary** | 資管領域的官方文獻庫（MISQ、ISR、JAIS、CAIS 等）；CAIS 與部分內容開放取用 | <https://aisel.aisnet.org/> |
| **臺灣博碩士論文知識加值系統** | 國家圖書館的全國碩博士論文檢索 | <https://ndltd.ncl.edu.tw/> |
| **你自己學校的圖書館電子資源** | Web of Science、Scopus、ScienceDirect、EBSCO、華藝等付費資料庫的**唯一合法入口** | 各校圖書館網站 |

!!! warning "先去圖書館開好校外連線"
    絕大多數頂級期刊要付費。**學校已經幫你買了**，但你必須先設定校外連線（VPN 或 proxy），否則在家永遠只看得到摘要。這件事第一週就該做完，它會影響你之後每一天的效率。
    另外：**不要用來路不明的網站抓付費論文。** 那是侵權，而且很多研究倫理課程會直接把它列為違規事項。找不到全文時，正規做法是圖書館的館際合作／文獻傳遞服務，或直接寫信向作者索取（多數作者會給）。

### 2.3 關鍵字怎麼組

新手最常見的失敗是「關鍵字太自然語言」。學術檢索要用**術語**，不是用你想問的句子。

四個技巧：

1. **同義詞展開。** 同一個概念在不同流派有不同叫法（continuance / continued use / post-adoption；適配 / fit / alignment）。先讀一篇回顧型論文，把它用的術語抄下來當關鍵字。
2. **引號鎖詞組。** `"task-technology fit"` 只會找到這個完整詞組，比三個字分開找精確得多。
3. **布林組合。** `("generative AI" OR "large language model") AND ("academic writing" OR "scholarly writing")`。用括號分組，不要全部串在一起。
4. **從一篇好論文的關鍵字欄抄。** 期刊論文的 Keywords 欄是作者精選的檢索詞，直接拿來用。

### 2.4 滾雪球：找到一篇好的之後怎麼繼續

找到一篇貼近你題目的好論文之後，**不要再回去搜尋引擎**，改用滾雪球：

- **向後滾（backward）**：讀它的參考文獻，往回找它站在誰的肩膀上。這條路會通到領域的經典。
- **向前滾（forward）**：用 Google Scholar 的「被引用次數」點進去，看誰引用了它。這條路會通到最新的發展與批評。

兩個方向各滾兩層，通常就足以把一個子題的文獻地圖畫出來。引文網絡工具（Connected Papers、ResearchRabbit、Litmaps）就是把這件事視覺化，介紹見[AI 學術研究工具指南](tool-directory.md)。

### 2.5 一篇值不值得花時間讀

在點開全文之前，用五個訊號快速篩：

| 訊號 | 怎麼看 |
|---|---|
| **發表在哪** | 期刊層級（資管可參考 AIS 頂級期刊清單）＞ 好的會議 ＞ 一般會議 ＞ 不明來源 |
| **被引用次數** | 相對於年份看：發表五年被引 200 次，跟發表二十年被引 200 次不是同一回事 |
| **摘要裡有沒有你的構念** | 摘要沒提到，內文通常也不會有 |
| **方法對不對** | 你要做量化，一篇純概念文章幫不上第三章 |
| **有沒有全文** | 只有摘要拿不到全文的，先放進「待處理」，不要卡在那裡 |

!!! danger "掠奪性期刊"
    有一類期刊收錢就刊、沒有實質審查。特徵包括：投稿到刊登只要幾週、網站上滿是「Impact Factor」的自製標章、編委名單查無此人、寄垃圾信邀稿。**引用了它們會扣分。** 不確定時，用期刊名稱去問圖書館館員，或查該領域的公認期刊清單。

### 2.6 「我的題目都找不到文獻」

這句話幾乎都是誤判。四種可能，依機率排序：

1. **關鍵字用錯了**（最常見）。你用的是自己的話，不是領域的術語。
2. **層級找錯了**。你的題目是「A 技術用在 B 產業」，但文獻分別在「A 技術」和「B 產業」兩邊，沒有人剛好合起來寫。**那正是你的缺口**，不是沒有文獻。
3. **範圍太窄**。往上抽一層：把「大學生使用某 App」抽象成「特定使用者族群的持續使用行為」。
4. **這個題目真的沒人做**。這種情況很少，而且要先確認不是因為它**不值得做**（沒有理論意義、拿不到資料、結論無法推論）。

## 三、怎麼讀 paper

### 3.1 先換掉閱讀順序：Outcome First

論文的排版順序是給審查者看的，不是給學習者看的。照第一頁讀到最後一頁，你會在還不知道這篇要幹嘛的時候，先被三頁文獻探討淹死。

實務上效率最高的順序是**逆向的**：

```
① 摘要          全局，30 秒決定要不要繼續
② 研究模型圖    先看 Y（依變數），再看 X（自變數）
③ 問卷／測量題項  作者「真正量到的東西」，定義常常藏在這裡
④ 緒論          它憑什麼說這個問題重要、有趣？
⑤ 研究方法      設計、順序、樣本
⑥ 結果與討論    數字回填到模型圖上
```

!!! tip "為什麼是「先看 Y 再看 X」"
    因為 **X 導致 Y**，而 Y 才是這篇論文的主題。先知道作者想解釋什麼，你才有辦法判斷他挑的那些 X 合不合理。
    順序反過來，你會變成被作者的變數清單牽著走，喪失判斷力。
    這個原則之後會一路用到底：講模型時從右邊講起、寫第五章時先寫結論、做簡報時標題寫結論句。

**第 ③ 步最常被跳過，也最值錢。** 論文正文裡的構念定義通常寫得很抽象，但附錄的問項是具體的句子。看完問項，你才會知道作者說的「信任」到底是指什麼；要借用量表，也是從這裡開始。

### 3.2 遇到看不懂的天書：螺旋式閱讀

完全讀不懂的論文，**不要從第一個字硬啃到最後一個字**。改成一圈一圈往內收：

| 圈次 | 讀懂多少 | 做什麼 |
|---|---|---|
| **第一圈** | 10–20% | 只做一件事：**把看不懂的核心關鍵字抓出來**，去補科普級／入門級的背景知識，然後回來 |
| **第二圈** | 30–40% | 掌握研究骨架與模型圖：它在解釋什麼、用什麼解釋 |
| **第三圈** | 需要的部分 | 只挑跟你的研究高度相關的那一節（通常是方法或結果）精讀 |

這個做法的價值在於**承認你現在讀不懂是正常的**，並且把「讀不懂」拆成可以處理的步驟，而不是變成放棄的理由。

!!! note "想看更完整的版本"
    這一節與 §3.4 是把常見的做法整理成可執行的流程，**不是任何一本書的內容摘要**。
    相近的觀念在彭明輝《研究生完全求生手冊》與他的〈期刊論文閱讀技巧〉講座裡有完整得多的論證與示範，本站只做通則式的重述。要真正學會，請看原書與原講座（見[延伸閱讀與資源指南](sources.md)第二節與第四節）。

- [ ] 卡住時的固定動作：抓出 **3 個** 需要先查的背景關鍵字，去查完再回來。

### 3.3 三遍法：先決定值不值得往下讀

最廣為引用的框架是 Keshav 的**三遍閱讀法（three-pass approach）**：

| 遍數 | 花多久 | 讀什麼 | 讀完要能回答 |
|---|---|---|---|
| **第一遍** | 5–10 分鐘 | 標題、摘要、模型圖、各節標題、結論 | 這篇在做什麼？**我要不要讀第二遍？** |
| **第二遍** | 約 1 小時 | 正文（跳過推導細節）、看懂所有圖表 | 它的主張、證據、方法是什麼？我能不能講給別人聽？ |
| **第三遍** | 數小時 | 逐行重建，假設自己是作者 | 隱藏假設是什麼？哪裡站不住？換成我會怎麼做？ |

- Keshav, S. (2007). How to Read a Paper. *ACM SIGCOMM Computer Communication Review*, 37(3), 83–84. <https://dl.acm.org/doi/10.1145/1273445.1273458>

**大部分論文你只需要第一遍。** 一輪文獻回顧裡，第一遍：第二遍：第三遍的比例大概是 30：8：2。把時間花在該花的那兩篇上，是文獻回顧唯一的效率來源。

### 3.4 五個層次：每一層要花多久、要交出什麼

三遍法回答「讀多深」，但沒有規定**每一層要留下什麼**。加上產出物之後，它才會變成可執行的流程。**沒有產出物的閱讀，三個月後等於沒讀過**。

| 層次 | 時間 | 目標 | 必要產出 |
|---|---|---|---|
| **① 掃讀**<br>Skimming | 10 分鐘 | 判斷這篇是否值得繼續讀 | **一句話總結**：「這篇用 ⟨理論⟩ 探討 ⟨對象⟩ 的 ⟨依變數⟩。」<br>（讀不懂時追加：3 個先備關鍵字） |
| **② 結構性閱讀**<br>Structural | 30 分鐘 | 掌握骨架與邏輯主線 | **四句話筆記**：研究問題（Y）→ 研究方法（X→Y）→ 主要發現 → 學術貢獻 |
| **③ 精讀**<br>Analytical | 60–90 分鐘 | 拆解變數操作化與方法論嚴謹度 | **一列摘要表**：研究問題（Y）／理論與模型（X）／方法與樣本／主要結果（含**不顯著與反常的發現**） |
| **④ 批判性閱讀**<br>Critical | 30–60 分鐘 | 化身嚴厲審查者 | **2 個優點 + 2 個致命限制** |
| **⑤ 綜合與轉化**<br>Synthesis | 持續累積 | 把別人的終點變成你的起點 | **匯入文獻矩陣**，並填上「我的切入點」與「風險與備胎」 |

三個實作要點：

1. **層次是可以停的。** 大多數論文停在①或②；只有跟你的題目正面相關的那幾篇需要走到④⑤。
2. **③的「不顯著與反常的發現」不要漏。** 那通常是最有價值的一格。一個作者自己解釋不了的結果，往往就是你的研究缺口。
3. **⑤是唯一會累積的一層。** ①到④是對單篇的處理，⑤才是把單篇變成你自己的知識體系。矩陣欄位見[文獻回顧與批判性思考](literature.md)。

!!! note "第④層具體要做什麼"
    扮演審查者時有三個固定的問題，比「找缺點」有效得多：
    **① 「那又怎樣」檢測**：結論是在驗證常識（廢話），還是真的讓人意外、挑戰了既有框架？
    **② 換場域檢測**：它是不是只是把舊模型套到新對象上，而沒說明新對象哪裡不一樣？
    **③ 致命傷檢測**：強迫自己寫出**兩個**限制。寫不出來代表你還沒讀懂，不代表這篇沒有限制。

### 3.5 依「你為什麼讀它」決定讀哪幾節

同一篇論文，目的不同，讀法完全不同：

| 你的目的 | 重點讀 | 可以略過 |
|---|---|---|
| 了解這個領域在幹嘛 | 摘要、緒論、結論 | 方法、分析 |
| 找研究缺口 | 緒論最後一段、討論、**未來研究方向** | 方法細節 |
| 借用它的理論 | 理論發展與假說推導那一節 | 資料分析 |
| 借用它的方法 | 研究方法、量表附錄、分析程序 | 理論鋪陳 |
| 借用它的量表 | **附錄的問項**與量表出處 | 幾乎全部 |
| 對它提出批判 | 研究限制、樣本、操作型定義 | 緒論 |

!!! tip "「未來研究方向」是題目的免費來源"
    每一篇論文的討論或結論都會列出未來研究方向，那是**作者本人認為值得做但自己沒做**的事。連讀十篇同主題論文的這一節，重複出現的那幾項就是這個領域公認的缺口。這是找題目最省力也最可靠的路徑之一。

### 3.6 關掉 PDF 之前的自我檢核

用自己的話回答下面六題。**答不出來的那一題，就是要回頭重看的地方。**

- [ ] **Outcome First**：這篇的依變數（Y）是什麼？這個問題在實務上為什麼重要？
- [ ] **邏輯骨架**：導致 Y 的自變數（X）是什麼？理論依據夠不夠堅實？
- [ ] **趣味與矛盾**：它有找出過去文獻的矛盾嗎？還是只是一篇驗證常識的報告？
- [ ] **方法論審計**：他發問卷／做實驗的順序合理嗎？測量指標精確嗎？
- [ ] **惡魔的代言人**：這篇的**兩個致命限制**是什麼？
- [ ] **創新與求生**：它可以成為我的「舊瓶」或「舊酒」嗎？如果我模仿它的做法，最容易卡關的地方在哪？備胎方案是什麼？

最後一題常被跳過，但它是這份清單裡唯一朝向**你自己的論文**的問題。前五題是理解別人，第六題才是把別人的東西變成你的。

完整的筆記欄位範本見[文獻管理與知識庫](tools-knowledge.md)。

### 3.7 讀不懂的時候，依序排除

1. **缺前置知識？** 論文預設你懂它引用的那個理論。先去讀原始文獻或一篇回顧（＝§3.2 的第一圈）。
2. **卡在統計？** 先看圖表與結論怎麼講，統計細節之後再補。看不懂 PLS 報表，不代表看不懂這篇的主張。
3. **原文表達不夠清楚？** 這很常見。換一篇同主題的讀，往往就通了。
4. **英文問題？** 用 AI 輔助理解句子結構是合理的用法；**但不要讓 AI 代替你判斷它的貢獻與缺陷**，那正是你要練的能力。分寸見[AI 輔助研究工作流](ai-workflow.md)。

## 四、怎麼選題目

### 4.1 「找一個你有興趣的題目」是個危險的建議

這是最常聽到、也最容易讓人後悔的一句話。彭明輝在部落格〈如何選研究的主題〉裡對這個建議提出明確的質疑：他主張真正該問的不是「我對這個題目有沒有興趣」，而是**「我在這個題目上有沒有『見人所未見』的能力」**，因為學位論文的成敗關鍵在於原創性貢獻，而興趣不保證你在那個題目上看得比別人深。

- 彭明輝，〈如何選研究的主題〉，清大彭明輝的部落格。<https://mhperng.blogspot.com/2022/11/blog-post.html>

實務上的翻譯：**興趣是必要條件，不是充分條件。** 兩年的研究會消磨掉大部分的興趣，撐到最後的是「我在這裡做得出別人做不出的東西」這個判斷。

### 4.2 缺口有五種

「研究缺口」不是一個模糊的詞，它有具體的類型。對照文獻檢查你的題目屬於哪一種：

| 缺口類型 | 長什麼樣 | 你要做的事 |
|---|---|---|
| **證據缺口** | 不同研究得到**矛盾的結論** | 找出造成矛盾的調節變數或情境差異 |
| **知識缺口** | 理論預期會有某個關係，但沒人測過 | 補上這個檢驗 |
| **方法缺口** | 既有研究的方法有明確弱點（樣本、測量、橫斷面） | 用更嚴謹的方法重做 |
| **理論缺口** | 現有理論解釋不了某個新現象 | 提出延伸或整合，並說明機制 |
| **情境缺口** | 理論沒被用到某個情境，而**該情境的某個特性理論上會造成差異** | 論證那個特性，再檢驗 |

!!! warning "情境缺口最容易被誤用"
    「這個模型還沒人用在台灣／用在某產業」**本身不是缺口**。你必須先指出這個情境的哪一個特性，會讓原理論的哪一個假設失效。說得出來才是缺口，說不出來就只是換地點重做。詳見[資訊管理研究的範疇與取向](is-research.md)的「複製／擴充／創造」。

### 4.3 收斂的漏斗

```
領域（資訊管理）
  ↓ 讀 3–5 篇回顧型論文
主題（例如：生成式 AI 在工作場域的採用）
  ↓ 讀 20–30 篇，找出爭議點
子題（例如：AI 輔助對使用者能力的長期影響）
  ↓ 找出具體缺口 + 確認資料拿得到
論文題目（明確到可以寫成一個問句）
  ↓
研究問題 + 假說（見 problem-design）
```

每往下一階，都要能回答「**為什麼要窄到這裡**」。窄不下去，通常是文獻讀得還不夠。

### 4.4 一個題目定案前的六個問題

- [ ] 我能用**一個問句**把它講完嗎？（講不完就是還太寬）
- [ ] 這個問題**有人在乎嗎**？誰？為什麼？
- [ ] 前人做到哪裡？我補上的是哪一種**缺口**？
- [ ] 我的**依變數**是什麼？我要解釋的到底是什麼？
- [ ] **資料拿得到嗎**？（樣本在哪、要多少、要多久、誰願意填）
- [ ] 兩年做得完嗎？做不完的話，**退而求其次**的版本長什麼樣？

第五題和第六題最常被忽略，也最常在計畫書口試被打回。

### 4.5 幾種一看就有問題的題目

| 壞題目的長相 | 問題在哪 |
|---|---|
| 「⋯⋯之研究」而沒有依變數 | 沒有要解釋的東西，就沒有研究問題 |
| 同時想回答三、四件事 | 戰線太長，每一件都做不深（見[研究的本質](research-basics.md)的「深而窄」） |
| 「探討 A 對 B 的影響」但 A、B 都沒有理論來源 | 變數是想出來的，不是文獻來的 |
| 需要拿到你拿不到的資料 | 可行性不過關 |
| 換個名詞就變成別人的論文 | 沒有屬於自己的情境特性或機制 |
| 結論不論怎樣都成立 | 不可否證（見[理論的構成與評估](theory-building.md)） |

## 六、本頁重點回顧

- 找、讀、選題是**螺旋**：找一輪 → 讀一輪 → 收窄一階 → 再來一輪，重複兩三次。
- 先讀**回顧型論文**建立地圖；中文碩博論文拿來當地圖，**引用要回到它引用的原文**。
- 關鍵字要用**領域術語**，不要用自然語言；找到一篇好的就改用**向前／向後滾雪球**。
- 讀論文用**三遍法**，而且大部分論文只需要第一遍；讀哪幾節取決於你為什麼讀它。
- 「未來研究方向」那一節是**題目的免費來源**。
- 選題該問的不是「我有沒有興趣」，而是「**我在這裡做不做得出別人做不出的東西**」。
- 缺口有五種；「還沒人做過某情境」本身不是缺口，**論證出情境差異**才是。
- 題目定案前先過六個問題，其中**資料拿不拿得到**與**兩年做不做得完**最常被忽略。
