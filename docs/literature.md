# 文獻回顧與批判性思考

> 文獻回顧不是「證明我讀了很多書」，而是「讓讀者清楚看見我要補的那個洞」。這一頁講搜尋、閱讀、彙整與寫作的完整流程。

!!! note "想看更完整的版本"
    這一整頁的骨架——文獻回顧的兩大積極功能、搜尋策略、批判性閱讀與彙整、寫作次序——高度相關於彭明輝《研究生完全求生手冊》，**不是任何一本書的內容摘要**，而是把書中觀點濃縮成可直接照做的流程。
    要看完整的論證與示範，請看原書（見[延伸閱讀與資源指南](sources.md)第二節與第四節）。

## 一、文獻回顧的兩大積極功能

一般人以為文獻回顧就是「整理前人做過什麼」。那只是最消極的功能。它真正的兩大功能是：

1. **彙整批判與檢視的原則和要領。** 從既有文獻歸納出這個研究主題需要注意的各種批判角度：從教科書定理的適用性、隱藏性假設、基本概念與現實世界的對應、統計方法的適切應用、研究設計、取樣範圍的爭議，到原始統計數據的可靠度。
2. **啟發創新的構想。** 分析既有答案的缺點與不足，找到突破的線索。

最後把創意與批判原則彙整成一個嚴謹而有價值的研究計畫。

> 文獻回顧的目的，並非只是消極地吸收文獻中的知識並加以整理，而是為了回答**你自己提出來的問題**，以及激勵進一步的思考與創意。

## 二、搜尋：四批文獻與三組關鍵字

文獻搜尋要同時達成三個要求：

1. 只保留跟主題密切相關的文獻，過濾掉不相關或品質較差的；
2. 涵蓋**所有具代表性的觀點與流派**，無所遺漏或偏廢；
3. 涵蓋每一個流派或觀點的**所有關鍵性論文**。

### 2.1 關鍵字的三輪迭代

這是最實用的一段流程，因為關鍵字選錯，後面全錯：

| 輪次 | 做法 | 產出 |
|---|---|---|
| 第一組關鍵字 | 憑直覺想出最接近研究主題的詞，透過英文版維基百科、圖書館主題編號、Google Scholar 搜尋 | **第一批論文** |
| 第二組關鍵字 | 從第一批論文中篩出最相關的，彙整**它們自己使用的關鍵字** | **第二批論文** |
| 第三組關鍵字 | 比對第二批論文的關鍵字，得到更精準、完整的一組 | 用來搜尋回顧型論文、博士論文、專書 |
| 引文索引 | 用各流派的**經典論文**做正向引文追蹤 | **第四批論文**（各流派最新文獻） |

!!! tip "資訊管理領域的搜尋提示"
    查論文時關鍵字**加上 information system**，可以有效把結果限縮在資管領域的脈絡；**有問卷的論文比較好讀**，因為它的構念、操作化與分析都攤開來了。另外，**PDF 一定要自己留存一份**，避免資料庫改版、連結失效或設備問題。

### 2.2 從什麼類型的文獻開始

順序是由寬而窄、由淺而深：

1. **回顧型論文（review article）**：了解主題的梗概，包括問題背景、發展歷程、子題的相互關聯、各種觀點與流派、代表性著作、爭議與共識、最新趨勢。
2. **教導型論文（tutorial）**：內容較淺白，但能深入淺出介紹背景與沿革，補上原創性論文常省略的部分。
3. **相關博士論文的文獻回顧章節**：通常寫得比期刊論文完整，且有中文的可以先讀。
4. **各流派的關鍵論文**：最後才逐一啃。

當你手上有好幾篇回顧型論文時，**按難易程度安排閱讀順序，先讀容易的**，最難的留到最後。

## 三、閱讀：像剝洋蔥一樣讀期刊論文

大學時代的教科書是精心組織過的材料，適合從第一頁讀到最後一頁。**期刊論文是寫給專家讀的**，你必須自己找出背景資料、擷取需要閱讀的章節、安排最有效的閱讀順序。

讀論文**不能急著一次就讀懂**。要像剝洋蔥一樣，一次讀懂一層，由外向內、由淺而深。每一次閱讀都只求增進下一次閱讀時的理解能力。

| 次數 | 目標 | 讀完後要做什麼 |
|---|---|---|
| 第一次 | 只讀懂最粗淺、易懂的部分 | 判斷自己還缺哪些背景知識，去找科普級文件 |
| 第二次 | 確定它屬於哪個學術領域、用什麼方法、想解決什麼問題、對應的術語是什麼 | 找入門級學術文件補背景 |
| 第三次 | 大約懂一、兩成 | 找主題或方法相近而易讀的書或碩博士論文，只讀相關章節 |
| 第四次 | 大約懂三、四成 | 粗略讀過這篇論文的參考文獻，找出有助理解的段落並讀完 |
| 第五次 | 大約懂七、八成 | 針對還不懂的部分，精準地找特定章節、頁次來讀 |

!!! note "與其一次讀懂一篇，不如一次讀懂一整批"
    同一主題的一批論文彼此有大量重疊的背景知識。批次閱讀的效率遠高於逐篇攻堅。**在你確定某批論文確實跟你的問題密切相關之前，不需要急著完全讀懂它們。**

### 3.1 讀論文的順序

一篇論文拿到手，建議的閱讀順序是：

1. **摘要**：這篇在做什麼、發現什麼
2. **研究架構圖**：模型長什麼樣子（先看 Y，再看 X）
3. **問卷／量測工具**：構念實際上是怎麼被測的
4. **緒論**：作者如何論證這個研究的重要性

這個順序的邏輯是：先掌握骨架，再看細節，最後才看作者怎麼包裝。

## 四、彙整：方法與應用場合特性對照表

這是《研究生完全求生手冊》裡最實用的一個工具，也是管理類論文常被要求的「文獻比較表」的嚴謹版本。

### 4.1 核心觀念

> **方法沒有絕對的好壞，只有相對的優缺點。** 優點再多的方法，用錯了地方就一無是處；缺點再多的方法，用對了地方也可圈可點。關鍵在於你有沒有為給定的問題情境找到最適用的方法。

### 4.2 一個方法的特性可以分成四大範疇

1. **基礎假設與適用範圍**：最難彙整，因為假設常隱藏在術語裡、散布於多篇論文的不同段落，甚至被專業學者自己忽略。
2. **應用上的難易程度與成本**
3. **常態工作條件下的性能表現**（亦即吻合基礎假設時）
4. **會影響性能的干擾因素，以及對干擾因素的耐受性**

後三項通常容易得多：論文會在摘要、序言與結論中反覆強調自己的優點，也會在序言中扼要摘述其他方法的缺點。

### 4.3 對照表怎麼做

表格分成左右兩半：

- **左半：應用場合特性表**：各種應用情境在意什麼、不在意什麼
- **右半：方法特性（優缺點）表**：各種方法在各項考量因素下的表現

!!! warning "不要把「綜合得分」拿來排名"
    把各方法的優缺點加總排名，是最常見的判斷錯誤。一個總分最低的方法，可能恰恰在某個應用場合最在意的兩項能力上表現優異，而它表現拙劣的兩項恰恰是該場合不在意的；那它就是該場合**唯一適用**的方法。

這張表的三個用途：

1. 選擇適用的研究方法
2. 指引創新策略（找到「以己之長，攻彼之短」的應用場合）
3. 撰寫論文時，決定要宣告什麼貢獻、預期會遭遇什麼質疑、要怎麼防守

### 4.4 管理類論文的文獻比較表

**管理類的論文最好做一個比較表。** 常見的欄位設計有三種：

| 欄位設計 | 適用 |
|---|---|
| 作者年份 ／ 研究目的 ／ 研究方法 ／ 樣本與情境 ／ 主要結果 | 想突顯「大家都做了什麼、都沒做什麼」 |
| 作者年份 ／ 採用理論 ／ 自變數 ／ 中介或調節 ／ 依變數 ／ 顯著結果 | 想突顯「我的模型跟別人差在哪」 |
| 作者(年份) ／ 研究對象 ／ 研究目的 ／ 研究結果 | 簡化版，見下方說明 |

!!! note "簡化版適合什麼情境"
    第三種欄位最少、最快填完，適合**文獻篇數多、想先做一輪全貌式整理**的階段——例如剛開始收斂主題、還在確認這個領域大致的版圖時。相對於前兩種欄位設計，這一版是用深度換效率：拿掉了研究方法、理論、變數關係這些細節，換來的是可以在短時間內把大量文獻掃過一輪。等主題收斂到真正要寫進論文的那幾篇，再回頭用前兩種較細緻的欄位補齊。

**表格下方的那一段歸納，才是表格存在的理由。** 用兩三句話點出「這些研究都做了什麼、都沒做什麼」，否則表格只是排版。

### 4.5 工作用的文獻矩陣：多兩欄，就從整理變成規劃

上面兩種是**要放進論文**的比較表。你自己平常維護的那一份，應該再多兩欄。這兩欄不會出現在論文裡，但整份研究的走向是靠它們決定的：

| 作者／年份 | 核心問題（Y） | 理論／方法（X） | 結論與矛盾點 | 致命限制 | 💡 我的切入點 | 🛡️ 風險與備胎 |
|---|---|---|---|---|---|---|
| A (2022) | ⟨依變數⟩ | ⟨理論⟩／問卷 | ⟨主要發現⟩ | 缺乏行為資料 | **新瓶舊酒**：模型微調後移到 ⟨新情境⟩ | 風險：⟨資料⟩ 難取得<br>備胎：改用訪談做質性分析 |
| B (2023) | ⟨依變數⟩ | 實驗法 | ⟨主要發現⟩ | 樣本僅單一族群 | **雁行**：接續它的缺口，換 ⟨對象⟩ 驗證 | 風險：實驗組招募困難<br>備胎：單組前後測設計 |

- **💡 我的切入點**：每讀完一篇就強迫自己填一句。填不出來，代表這篇對你的論文其實沒用，那就不必再花時間。
- **🛡️ 風險與備胎**：如果你打算模仿這篇的設計，資料好不好拿？拿不到的話退一步的版本是什麼？**這一欄是計畫書口試的可行性評估的草稿**（見[計畫書、口試與簡報](defense.md)）。

!!! tip "這兩欄的真正作用"
    它們把文獻回顧從「整理別人做了什麼」變成「規劃我要做什麼」。
    多數人的文獻矩陣停在第五欄，於是讀完三十篇之後仍然不知道自己要做什麼，因為**從來沒有一個欄位逼他們回答那個問題**。
    欄位範本與知識庫做法見[文獻管理與知識庫](tools-knowledge.md)。
    另外注意，這張表是**以文獻為單位**的工作表，跟 §5.5 那張**以概念為單位**的概念矩陣不是同一張：這張決定你要做什麼，那張決定文獻探討怎麼寫。

## 五、寫作：文獻探討每一節的三層結構

### 5.1 第一層：理論定位（1–2 段）

要回答三件事：

- 這個理論解釋了什麼？
- 它在你的模型裡扮演什麼角色？（前因？中介？框架？）
- 它解釋到哪裡就停了？

**不好的開場**：「X 理論由 Author (Year) 提出，是目前最具影響力的理論之一。」（空泛、AI 感重）

**好的開場**：「⟨某理論⟩ 解釋了使用者為何採納一項新科技，但它的終點是使用意圖，不及於實際的使用深度。意圖是理性評估的產物，使用深度受情境條件左右，兩者機制不同。」

差別在於：好的開場第一段就告訴讀者這個理論**能做什麼、不能做什麼**。

### 5.2 第二層：相關實證（表格 + 一段歸納）

- 用表格整理同類研究
- 表格下方用 2–3 句話點出共通點與空白處

### 5.3 第三層：本節小結（1 段）

**不好的小結**：「本節回顧了 X 理論的相關文獻。」（讀者剛讀完，不需要你複述）

**好的小結**：說清楚這個理論在你模型裡的角色、指出它解釋不了的部分、銜接到下一節。

### 5.4 論證，不是報告

判斷一節文獻探討寫得好不好，只要看它是**論證**還是**報告**：

| | 報告（不合格） | 論證（合格） |
|---|---|---|
| 句子的主語 | 一直是別的作者 | 是**現象**與**問題** |
| 段落功能 | 摘要別人做了什麼 | 一步一步逼出你的假說 |
| 讀完的感覺 | 知道有很多人研究過 | 知道**為什麼非做你這一題不可** |

不合格的長相：

> ❌ Davis（1989）指出⋯⋯。Venkatesh 等人（2012）也指出⋯⋯。因此本研究⋯⋯

每一小節該跑的論證鏈是固定的四步：

> ✅ **① 這個現象／構念存在**（文獻 A、B）
> → **② 但既有解釋有缺口**（文獻 C 只做到這裡，或 C 與 D 的結論互相矛盾）
> → **③ 本研究用這個方式填補**（換情境／換方法／補中介，並說明為什麼這樣補有效）
> → **④ 因此提出 H*n***

把這四步當成模板，每一節照著跑一次。**第②步是全篇最值錢的地方**；沒有第②步，第④步就沒有立足點，口試委員一定會從那裡切進來。

!!! tip "怎麼檢查自己寫的是哪一種"
    把整節的引註全部遮起來再讀一次。如果遮掉之後論證還讀得通，那是論證；如果剩下一堆「某某指出」的空殼，那是報告。
    這一招是**總檢**，不是唯一的檢查。它抓不到下一節要處理的那種失敗：每一句都有實質內容、句與句之間卻沒有關係。

### 5.5 文獻是在對話，還是只是並列？四個具體檢查

!!! note "這一節的來源"
    本節依據 Webster, J., & Watson, R. T. (2002). *Analyzing the past to prepare for the future: Writing a literature review.* **MIS Quarterly**, 26(2), xiii–xxiii.（見[延伸閱讀與資源指南](sources.md)第三節）與大學寫作中心關於 synthesis matrix 的公開教學。

Webster & Watson 這篇是資管領域文獻回顧的方法論經典，核心主張只有一句：文獻回顧必須是 **concept-centric（以概念為中心）**——「概念決定一篇回顧的組織架構；相對地，有些作者採取以作者為中心的寫法，實際上只是把相關文章摘要一遍，這種做法無法整合文獻。」

他們給的工具是**概念矩陣**：以文獻為列、概念為欄，必要時再依分析層次（個人／團隊／組織）切分子欄。

| | 概念 A | 概念 B | 概念 C |
|---|---|---|---|
| 甲 (2019) | ✓ | | ✓ |
| 乙 (2021) | ✓ | ✓ | |
| 丙 (2023) | | ✓ | ✓ |

寫作時的關鍵動作是：**橫著寫一欄，而不是直著寫一列。** 一列一列寫下去就是「甲說……乙說……丙說……」的摘要；一欄一欄寫，才會逼你回答「這三篇對概念 A 各說了什麼、彼此是什麼關係」。這張表也可以反過來檢查已經寫好的稿子。

#### 檢查一：主語掃描

把這一段每個句子的主語標出來，分成「某文獻／某作者」和「現象／構念／問題」兩類。

- 連續兩句以上主語都是**不同的**文獻名 → 這是證據並列。
- 一段之內文獻當主語的句子超過一半 → 這段是報告。

❌ 並列：

> 甲（年）以 ⟨樣本一⟩ 發現 X 現象普遍存在。乙（年）針對 ⟨樣本二⟩ 的調查也顯示 X 的比例偏高。

✅ 對話：

> X 現象在 ⟨樣本一⟩ 與 ⟨樣本二⟩ 都被記錄到（甲, 年; 乙, 年）。兩者母體不同卻指向同一方向，「X 只是特定族群的現象」這個解釋因此站不住。

#### 檢查二：關係詞測試

只要同一段落出現兩篇以上文獻，就必須有一句話明講它們之間是哪一種關係。可用的關係只有五種：

| 關係 | 判準 | 該補上的那一句長什麼樣 |
|---|---|---|
| 一致補強 | 不同樣本／方法得到同方向結果 | 「兩者樣本與方法都不同卻指向同一方向，⟨結論⟩ 不太可能是 ⟨某種偏誤⟩ 造成的。」 |
| 分歧 | 結論相反，或效果量差距明顯 | 「甲得到 X，乙卻得到 Y；差異可能來自 ⟨測量／樣本／情境⟩ 的不同。」 |
| 互補 | 各自涵蓋不同面向或分析層次 | 「甲處理的是 ⟨個人層次⟩，乙處理的是 ⟨團隊層次⟩，兩者合起來仍未觸及 Z。」 |
| 遞進 | 後者在前者基礎上往前推一步 | 「乙把甲的 ⟨某條件⟩ 放寬到 ⟨新條件⟩，但仍沿用了 ⟨某假設⟩。」 |
| 條件化 | 後者指出前者只在某條件下成立 | 「乙顯示甲的結果只在 ⟨某條件⟩ 下成立。」 |

!!! warning "「都支持同一個結論」不是一種關係"
    那是同一格被填了兩次。兩篇文獻對這一段的功能如果完全相同，正確做法是**合併引註寫成一句**（「⟨現象⟩ 已在多個情境被記錄（甲, 年; 乙, 年）」），把省下來的篇幅拿去寫缺口。功能相同卻拆成兩句各講一遍，就是證據並列。
    一句話自問：**把其中一篇刪掉，這一段會少掉什麼？** 答不出來，就合併。

#### 檢查三：伏筆兌現

矩陣裡每個概念都該有一欄。**一個只填了一格、後面再也沒出現的概念，就是沒兌現的伏筆。**（Webster & Watson 提出矩陣是用來組織文獻的；把它反過來當自己稿子的自檢工具，是本站的延伸用法，不是原文的主張。）

做法：把這一節出現的每個概念名詞圈出來（不含作者名、不含研究方法名），查它最後一次出現在哪裡。每個概念必須落到三種歸宿之一：

1. **被用掉**：進入缺口論述，或成為假說裡的變數。
2. **被劃界**：明說「本研究不處理 ⟨這個概念⟩，因為 ⟨理由⟩」。
3. **被刪掉**。

速判規則：**只出現一次、而且那一次不在本節小結或假說句裡的概念，一律列為待處理。**

❌ 伏筆沒兌現：

> ⟨某理論⟩ 把因應方式分成 Y 與 Z 兩類。本研究關注 Y 對 ⟨結果變數⟩ 的作用……（此後 Z 再也沒出現）

✅ 兌現（走「被劃界」）：

> ⟨某理論⟩ 把因應方式分成 Y 與 Z 兩類。本研究只處理 Y；Z 需要 ⟨某種資料⟩ 才觀察得到，橫斷面問卷設計涵蓋不了。

!!! tip "為什麼劃界比刪掉更值得寫"
    口試委員看到 Z 沒被處理，第一個問題就是「那 Z 呢」。事先劃界等於把這一問答完，還順便展示你知道理論的完整版圖。

### 5.6 引用整合技巧

| 情境 | 做法 | 範例 |
|---|---|---|
| 多篇研究同結論 | 合併引註 | 「⟨某現象⟩ 與 ⟨某結果⟩ 顯著相關（作者甲, 年; 作者乙, 年）。」 |
| 研究結果分歧 | 明確呈現分歧並分析原因 | 「A 以 ⟨樣本一⟩ 發現 X，B 以 ⟨樣本二⟩ 卻發現 Y。差異可能源自……」 |
| 引用經典定義 | 一次給完，後續不再重複 | 「⟨作者⟩（年）把 ⟨構念⟩ 定義為……」之後直接用該術語 |
| 連續以「Author (Year)」開頭 | 最多兩段，第三段必須換開法 | 以現象、觀察、反問或短句開頭 |

### 5.7 文獻探討的具體要求

- 要有**最近五年**的文獻
- 盡量引用**重量級、高引用**的原著（不要只引二手轉述）
- 引用好的文獻、豐富的內容、必要的鋪陳都會加分
- 文獻不只是摘要，**要說明它對本研究的意義**：補充了什麼？留下什麼缺口？

## 六、「六經皆我注腳」：參考文獻的正確角色

> 參考文獻的功能既非用來證明作者的知識廣度，更不可以淪為炫耀知識或**只敘不評的流水帳**。

引註文獻的正當目的只有三個：

1. **補充**作者在論文中未及詳言的細節或事實
2. **佐證**作者的觀點與主張
3. **宣告（承認）前人的貢獻**，以避免剽竊的嫌疑

與此無關的文獻就不該納入。**參考文獻並非越多越好；隨意引註跟論文內容無關的論文乃是大忌。**

### 6.1 導論裡文獻的角色是配角

導論與文獻回顧的主角只有兩個：**研究主題的意義與價值**，以及**本研究在觀點、理論、證據與方法上的創新**。既有文獻是用來佐證前述論述的附屬配角，篇幅不該蓋過主角。

!!! warning "口試委員可能隨機抽考你引用的文獻"
    為了確認是否有浮濫引註，有些評審會從參考文獻清單隨機抽出幾篇來問你，看你是否確實讀過（至少讀過跟引註有關的部分）。**確保你讀過每一篇自己引用的論文。**

### 6.2 影響論文評價的三個文獻相關因素

- 文獻回顧的**完整度**
- 文獻引述的**正確性**
- 所引文獻是否能**有效應用**

後兩項提醒我們：文獻回顧雖然必須完整，但忌諱浮濫和浮誇，更忌諱未經查證就以訛傳訛，抄襲前人的錯誤引註。

## 七、文獻回顧與批判性思考的關係

專業領域裡的嚴謹思考通常始於定義問題，繼而從周延的觀點審視問題的各個面向，然後彙整證據、檢證可信度，之後歸納、提出假說、演繹論證，獲得新發現並做出結論，最後闡述其延伸意涵與重要性。

**這整個過程所需要的批判性思考，幾乎都已經具體而微地表現在相關的文獻裡。** 只需要適切地彙整並充分吸收，就足敷論文寫作的需要。

這推導出一句極重要的話：

> 「別讓口試委員問到任何你沒想過的問題。」

這不是要你未卜先知。它的真正意思是：**口試委員再怎麼傑出，他的批判性思考很難超出既有文獻所匯聚的學界智慧。** 只要你的文獻回顧做得比一般研究生更周延、詳盡、扎實，別人就很難問出你沒想過的問題；就算他碰巧想到某個你遺漏的角度，你紮實的文獻回顧也會讓那個疏失變成「瑕不掩瑜」。

### 7.1 寫完每一節後的三個自問

1. 你為什麼用**這個理論**而不用別的？（替代方案的回應）
2. 這個理論有什麼**限制**是你還沒處理的？（研究限制的預先處理）
3. 你的**操作型定義**跟原始定義有什麼差異？為什麼？（構念效度的防禦）

如果這三個問題都能在文獻回顧的敘述中找到答案，這一節就寫得夠紮實了。

## 八、創新的三種典型

文獻回顧做完之後，創新的機會通常長成這三種樣子：

| 類型 | 意思 | 常見手法 |
|---|---|---|
| **舊瓶新酒** | 以新的證據、觀點或更嚴謹的方法重探舊題目 | ① 採用較新穎或較嚴謹的方法<br>② 分析既有文獻中的**矛盾結論**，找到化解矛盾的方法<br>③ 田野或實驗中的意外發現，突顯既有理論的瑕疵 |
| **新瓶舊酒** | 把既有方法適度修改後，探究新的領域或題目 | 先找到跟新領域關係最密切的舊領域，分析兩者異同，評估哪些原理可以沿用、哪些必須調整 |
| **雁行**（跟飛） | 尾隨一個剛出現的重大突破，接續它明確留下的缺口往下做 | 鎖定一篇近期的關鍵論文，把它「未來研究方向」列出的其中一項做完，並說明為什麼那一項值得先做 |

前兩種出自《研究生完全求生手冊》對創新策略的討論；第三種是實務上常見的做法，風險最低但時效性也最強，**跟得太慢就會被別人先做完**。

!!! warning "三種都要說明正當性"
    不管走哪一條，第二章結尾都必須明講：**原研究的哪一個限制或缺口，是我要處理的？** 沒有這一句，三種都會被讀成「換個地方重做一次」。判準見[資訊管理研究的範疇與取向](is-research.md)的「複製／擴充／創造」。

!!! note "創新不是對過去的否定"
    連革命也不是對過去的否定，兩者都是站在巨人的肩膀上，既承繼且創新。**創意不需要多，只需要在刀口上一個關鍵的發現。** 在嚴謹的演繹體系裡，只要一個關鍵性的事實或命題被改變，即使其他假設全部不變，往往也會演繹出一個全新的學術藍海。

## 九、本頁重點回顧

- 文獻回顧的兩大功能：**彙整批判要領**、**啟發創新構想**。
- 關鍵字要跑三輪迭代；再用經典論文做引文索引，拿到各流派最新文獻。
- 讀論文像剝洋蔥，一次讀懂一層；一次讀一整批比逐篇攻堅有效率。
- 讀論文順序：摘要 → 架構圖 → 問卷 → 緒論。
- 「方法與應用場合特性對照表」是選方法、找創新、寫防守論述的同一張表。
- 每一節文獻探討的三層結構：理論定位 → 相關實證（表 + 歸納）→ 本節小結。
- **論證不是報告**：現象存在 → 但有缺口 → 我這樣填 → 因此提出 Hn。遮掉引註還讀得通，才是論證。
- 文獻要**對話**不要並列：以概念為中心（Webster & Watson, 2002）橫著寫一欄而不是直著寫一列；同段兩篇以上文獻要明講關係（一致補強／分歧／互補／遞進／條件化），「都支持同一個結論」不算關係，該合併引註；每個登場的概念都要被用掉、被劃界或被刪掉。
- 工作用的文獻矩陣要多兩欄：**我的切入點**與**風險與備胎**，它們把整理變成規劃。
- 創新有三型：舊瓶新酒、新瓶舊酒、雁行；三種都要說明「原研究的哪個缺口是我要處理的」。
- 六經皆我注腳：文獻是配角，你的缺口才是主角。
- 只要文獻回顧夠紮實，口試委員就很難問出你沒想過的問題。
