# AI 學術研究工具指南

> 依研究階段分類的工具清單。重點不是「有哪些工具」，而是「哪一段流程值得交給工具，哪一段不能」。

!!! warning "先讀這段再看清單"
    這份清單只描述工具**能做什麼**，不代表你**被允許用它做什麼**。實際能否使用、使用到什麼程度與如何揭露，會因系所、指導教授、研究倫理審查與投稿單位而異，請逐一確認適用規範。

    另外：**所有工具的功能、涵蓋範圍與收費方案都會變。** 本頁的數字是 2026 年 9 月查詢官方網站當時的說法，使用前請自行到官網確認現況。

---

## 一、怎麼用這份清單

### 1.1 三個層級，責任不同

| 層級 | 工具做什麼 | 你必須做什麼 |
|---|---|---|
| **索引層**（找得到） | 幫你找到論文的存在 | 判斷相關性 |
| **理解層**（讀得懂） | 摘要、翻譯、問答、視覺化 | **開原文確認它沒有講錯** |
| **判斷層**（用得對） | 工具不能代替判斷 | 全部由你負責 |

愈往下，工具能幫的愈少，你要負的責任愈大。這條線就是本站反覆講的那句話：**AI 處理資訊密集但低判斷含量的工作。**

### 1.2 選工具的五個問題

1. 它覆蓋研究流程的哪一段？
2. 它的引用驗證機制是什麼？
3. 人類可以在哪裡介入？
4. 資料會送到哪裡？（涉及受訪者資料時這是倫理問題）
5. 授權條款允許什麼用途？

### 1.3 通用資料治理核對框

- [ ] **隱私**：上傳前已移除可識別個人或機構的資訊，且資料處理符合知情同意與倫理審查。
- [ ] **保存**：已確認服務是否保留輸入、保留多久，以及能否刪除；敏感資料另依研究計畫保存。
- [ ] **授權**：已確認輸入材料與輸出內容的使用條款，不上傳未獲授權的全文或資料。
- [ ] **匯出**：已實際測試原始資料、書目、註記與分析紀錄能否用可讀格式匯出。

### 1.4 一條不能妥協的紀律

> **凡是要寫進論文的引用，都必須自己開過原文。**

工具告訴你「這篇文獻存在」，跟「這篇文獻真的說了那句話」，是兩件事。[口試委員可能隨機抽問你引用的文獻內容](literature.md)。

## 二、階段一：題目探索與環境掃描

目標是**建立領域地圖**，不是找到定稿的文獻清單。這個階段容許「寬而淺」。

| 工具 | 定位 | 適合用在 | 注意 |
|---|---|---|---|
| **Perplexity** | 帶引用的網路搜尋 | 快速摸清一個陌生名詞的輪廓 | 來源包含大量非學術網頁 |
| **ChatGPT / Claude / Gemini 的深度研究模式** | 多輪搜尋後產出長篇報告 | 環境掃描、跨領域術語橋接 | 引用必須逐條查核 |
| **Elicit** | 學術論文的 AI 研究助理 | 從研究問題直接找出相關實證研究 | 見下節 |
| **Consensus** | 針對「某個主張是否成立」的學術搜尋 | 快速看某個因果主張的文獻分布 | 「多數研究支持」不等於「成立」 |

!!! tip "這個階段的正確心態"
    你要的是**版圖**，不是答案。一個動不動就丟給你上百條文獻的報告，初看豐富，實則會讓你淹沒在資訊洪流裡。
    先寫好[納入與排除準則](ai-workflow.md)，再啟動任何工具。

## 三、階段二：文獻檢索與發現

### 3.1 基礎檢索

| 工具 | 特性 | 為什麼你需要它 |
|---|---|---|
| **Google Scholar** | 涵蓋最廣，含灰色文獻與碩博士論文 | 引文追蹤（"被引用次數"）與 Alert 功能 |
| **Semantic Scholar** | Allen Institute for AI（AI2）維運的免費學術搜尋引擎，索引超過 2 億篇論文 | 提供 TLDR 摘要、引文脈絡、Semantic Reader、開放 API 與 S2ORC 語料庫 |
| **Scopus / Web of Science** | 商業資料庫，收錄經篩選 | 期刊分級、JCR/SJR 影響指標、系統性回顧的標準來源 |
| **華藝線上圖書館（airiti Library）** | 中文期刊與論文 | 中文文獻不可繞過的一站 |
| **臺灣博碩士論文知識加值系統** | 全台碩博士論文 | 看同領域學長姊怎麼做、抓研究缺口 |

### 3.2 AI 輔助檢索

**Elicit**（[elicit.com](https://elicit.com/)）

- 官網自述搜尋範圍超過 1.38 億篇學術論文與 54.5 萬筆臨床試驗
- 核心功能：Research Agent（跨來源蒐證並產出帶引用的報告、表格、圖表）、論文搜尋、系統性回顧的自動化篩選與**資料萃取**（把一批論文的樣本數、方法、結果抽成表格）
- 最有價值的用法：把「幫我找文獻」換成「幫我把這 30 篇的**研究設計欄位**抽成一張表」。這正是[文獻比較表](literature.md)的半自動版本
- 限制：抽取結果**必須逐格核對原文**；官網並未說明它不適用的情境

**Consensus**（[consensus.app](https://consensus.app/)）

- 定位是「科學研究的 AI 工作區」，2021 年創立，官網宣稱超過千萬名研究者、12,500 所以上大學使用
- 特色是把一個問句對應到一批實證研究，並呈現這些研究的立場分布
- **最大的誤用風險**：把「多數研究支持」當成「這件事成立」。研究數量不等於證據強度，而且發表偏誤（publication bias）會系統性地扭曲分布

**Undermind、Scite Assistant 等**

- 主打「深度搜尋」，用較長時間換較高的召回率
- 適合已經確定研究問題、要做窮盡式搜尋時；不適合題目還在漂移的階段

## 四、階段三：引文網絡與研究地圖

這一類工具解決一個具體問題：**你怎麼知道自己漏了什麼？**

| 工具 | 做什麼 | 適合的時機 |
|---|---|---|
| **Connected Papers** | 從一篇種子論文生成相似度圖譜，視覺化呈現該主題的論文群落 | 剛進入一個新主題，想快速看見「有哪些聚落」 |
| **ResearchRabbit** | 引文網絡視覺化 + Collections + 推薦引擎；官網稱可存取超過 3.1 億篇論文，可與參考文獻管理工具連動、追蹤新論文 | 需要**持續**維護一個文獻集合、並收到新文獻通知 |
| **Litmaps** | 以種子文獻為中心建立地圖並持續監看新增文獻 | 論文寫作期間避免遺漏最新研究 |
| **Inciteful** | 建立論文網絡並找出關鍵節點 | 想找出領域內的「必讀經典」 |
| **Open Knowledge Maps** | 依主題把搜尋結果分群成知識地圖 | 主題還很寬、需要先分群 |
| **VOSviewer / CiteSpace** | 書目計量（bibliometrics）分析與視覺化 | 要做**書目計量研究**本身，或想在文獻探討放一張正式的共被引圖 |

!!! note "視覺化圖不是文獻回顧"
    這些圖能告訴你「哪些論文彼此相關」，不能告訴你「哪一篇的理論框架適合我」。
    圖是**搜尋的輔助**，判斷仍然要靠[讀論文](literature.md)。
    另外，這類工具通常建立在特定的引文資料庫上，冷門主題或非英文文獻的覆蓋率會明顯偏低。

## 五、階段四：引用脈絡與證據品質

找到文獻之後，下一個問題是：**這篇後來有沒有被推翻？**

**scite**（[scite.ai](https://scite.ai/)）

- 核心是 **Smart Citations**：不只算「被引用幾次」，而是判斷後續研究**怎麼引用**它
- 三種分類：
  - **Supporting（支持）**：後續研究證實該論文的發現
  - **Contrasting（對照／質疑）**：後續研究提出相反或質疑的證據
  - **Mentioning（提及）**：提及但未直接支持或質疑
- 官網數據：索引超過 16 億筆引用陳述、3.17 億篇全文文章，與 35 家以上出版商有直接授權
- **對碩論最有用的一個動作**：把你打算當作理論基礎的那幾篇經典論文丟進去，看看有沒有大量 Contrasting。有的話，那就是你[文獻矛盾切入點](literature.md)的候選

**其他品質檢查**

- **Retraction Watch / 期刊的 retraction 公告**：確認你引用的論文沒有被撤稿
- **期刊本身的分級**：JCR、SJR、以及所屬領域公認的期刊清單（資管領域常參考 AIS Senior Scholars' Basket）
- **預印本的處理**：arXiv、SSRN 上的預印本**未經同儕審查**，引用時要標明並謹慎使用

## 六、階段五：閱讀與理解

| 工具 | 做什麼 | 風險 |
|---|---|---|
| **Gemini Notebook**（原 NotebookLM，Google 於 2026 年 7 月改名） | 只根據你**上傳的來源**回答並附出處，可產生摘要、大綱、問答 | 仍會誤讀；出處要點開確認 |
| **SciSpace** | PDF 逐段解釋、名詞解釋、跨論文比較 | 摘要可能抹平原文的限制條件 |
| **ChatPDF / Humata** | 針對單一 PDF 的問答 | 同上 |
| **Scholarcy** | 自動生成論文摘要卡片與關鍵詞 | 摘要卡不能取代閱讀 |
| **Semantic Reader** | 在閱讀介面中內嵌引文脈絡 | — |

!!! danger "摘要工具最危險的地方，不是它講錯，而是它講對但講不完"
    AI 摘要傾向保留「結論」而丟掉「條件」。一篇論文寫「在 A 條件下、以 B 樣本、用 C 方法，X 正向預測 Y」，摘要常常只剩「X 正向預測 Y」。
    把那句話直接寫進文獻探討，就會扭曲原作者的主張範圍。這正是[主張強度與證據強度匹配](style.md)那一節要防止的問題。

**限定來源型工具（如 Gemini Notebook）的一個優勢**：它只根據你給的來源回答，因此主要風險會轉為誤讀既有文獻。原文就在手上，研究者較容易逐項核對。

## 七、階段六：系統性文獻回顧

如果你的研究本身就是系統性文獻回顧（SLR）或 scoping review，這一組是專業工具。

| 工具 | 定位 | 特性 |
|---|---|---|
| **Rayyan**（[rayyan.ai](https://www.rayyan.ai/)） | 證據合成平台 | 完整流程：匯入 → 協作者分工 → 去重 → 題目摘要篩選 → 全文篩選與**衝突解決** → 資料萃取 → 偏誤風險評估 → 產出 PRISMA 流程圖；有免費方案 |
| **Covidence** | 同類商業平台 | 醫學領域常見，多半由機構訂閱 |
| **ASReview**（[asreview.nl](https://asreview.nl/)） | **開源**，由荷蘭 Utrecht 大學協調 | 以 **active learning** 加速標題與摘要篩選；官網稱可減少高達 95% 的篩選工作量，強調程式碼可驗證、使用者完全掌握資料與決策 |
| **PRISMA** | 不是工具，是**報告準則** | SLR 論文的標準骨架與流程圖規範 |

!!! warning "active learning 加速的是排序，不是決策"
    ASReview 這類工具的做法是：你標記幾篇之後，它把「最可能相關」的排到前面，讓你更早看完該看的。
    但**排序不是判斷**。納入／排除的準則要你自己定，邊界個案要你自己決定，而且必須記錄下來寫進論文。工具只是改變閱讀順序。

## 八、階段七：文獻管理與知識累積

多數 AI 研究工具輸出的是**一次性報告**，不會幫你累積資產。這一段要靠自己。

| 工具 | 角色 |
|---|---|
| **Zotero** | 免費開源的文獻管理器；瀏覽器外掛一鍵抓取、自動產生引用格式、支援 APA 7 中文化樣式 |
| **Zotero 外掛** | Better BibTeX（穩定的引用鍵）、ZotFile／Attanger（附件管理）、Zotero Style（視覺化補強） |
| **Mendeley / EndNote** | 同類替代；EndNote 在台灣許多學校有校園授權 |
| **Obsidian** | 以 Markdown 為主的知識庫；適合把文獻筆記與寫作草稿放在同一個庫裡 |
| **Notion** | 資料庫式筆記，適合做文獻矩陣表 |

### 8.1 一份文獻筆記至少要有的欄位

```
- 書目資訊（含 DOI）
- 研究問題
- 理論基礎
- 研究方法 / 樣本 / 情境
- 主要發現（含關鍵數值）
- 研究限制（作者自己承認的）
- 對我的研究的意義：補充什麼？留下什麼缺口？
- 可引用的句子（含頁碼）
- 查核狀態：我讀過原文了嗎？哪幾句是我親自確認過的？
```

**最後兩欄是整份筆記裡最重要的兩欄。** 沒有它們，你三個月後會分不清哪些是你讀的、哪些是 AI 摘的。

## 九、階段八：資料分析

| 類型 | 工具 | 備註 |
|---|---|---|
| 量化・SEM | **SmartPLS**（PLS-SEM）、**AMOS / LISREL / Mplus**（CB-SEM） | 選哪個要有[方法論依據](method-survey.md)，不是因為好操作 |
| 量化・一般統計 | **SPSS**、**JASP**、**jamovi**、**R**、**Python (statsmodels / scipy)** | JASP 與 jamovi 免費且介面友善，適合碩論 |
| 質性 | **NVivo**、**ATLAS.ti**、**MAXQDA**、**Taguette**（開源免費） | 編碼架構仍須研究者建立 |
| 機器學習 | **scikit-learn**、**PyTorch**、**Weka** | 見[演算法與資料分析](method-data.md) |
| 檢力分析 | **G\*Power** | 免費；實驗法應事前使用 |

!!! tip "AI 在這一段最實際的用途是寫程式碼"
    AI 可以協助起草 R 或 Python 分析程式碼，**但你必須看得懂每一行，而且能解釋分析邏輯**。
    看不懂就跑，等於把整章結果建立在你無法防守的基礎上。

## 十、階段九：寫作與語言

| 工具 | 用途 | 界線 |
|---|---|---|
| **Writefull / Paperpal / Trinka** | 學術英文的文法與用語修飾 | 屬語言協助；是否允許及如何揭露依投稿單位政策確認 |
| **Grammarly** | 一般英文文法檢查 | 同上 |
| **DeepL** | 翻譯 | 翻完必須自己逐句校對，術語尤其危險 |
| **Overleaf / LaTeX** | 排版（理工與部分期刊要求） | — |
| **Word 樣式與交互參照** | 中文碩論的主流 | 目次、圖表編號、交互參照都用內建功能做，不要手打 |

**中文寫作的關鍵風險**在別的地方：AI 生成的繁體中文極易混入大陸用語，而這是口試委員與審稿人最容易挑出來的。對照表與 grep 指令在[學術中文寫作紀律](style.md)。

## 十二、工具幻覺的三步查核

不管用哪一個工具，只要它產出了引用，就跑這三步：

| 步驟 | 做什麼 |
|---|---|
| ① 資料提取 | 從產出文字中抽出所有引用（作者、年份、標題、期刊、DOI） |
| ② 存在性查核 | 用 Google Scholar／Semantic Scholar／DOI 解析確認它**真的存在**，並標示 ✅ 通過 / ⚠️ 資訊有誤 / ❌ 查無此文 |
| ③ 內容查核 | **開原文**，確認它真的說了那句話，而且條件與範圍一致 |

第二步可以自動化，**第三步不行**。

## 十三、一個最小可行組合

如果你不想一次學十個工具，這是負擔最小又足夠用的一組：

```
檢索      Google Scholar + Semantic Scholar + 華藝 + 臺灣博碩士論文網
補漏      Connected Papers 或 ResearchRabbit（挑一個就好）
品質      scite（只用在你的核心理論文獻上）
閱讀      Gemini Notebook（只餵自己下載的 PDF）
管理      Zotero + Obsidian
分析      JASP 或 SmartPLS（依方法）
寫作      系所規定的 Word 模板 + 本站的檢查清單
```

**先把這套跑順，再考慮加東西。** 工具數量與研究品質沒有正相關。

## 十四、本頁重點回顧

- 工具分三層：索引層（找得到）、理解層（讀得懂）、判斷層（用得對）。第三層工具做不到。
- 凡是要寫進論文的引用，**都必須自己開過原文**。
- Elicit 最有價值的用法是**資料萃取成表**，不是找文獻。
- Consensus 的最大誤用風險是把「多數研究支持」當成「成立」。
- scite 的 Supporting／Contrasting 分類，是找研究矛盾最快的入口。
- 摘要工具最危險的不是講錯，是**講對但丟掉條件**。
- SLR 工具（Rayyan、ASReview）加速的是排序與流程，不是納入排除的判斷。
- 文獻筆記一定要有「對我的意義」與「查核狀態」兩欄。
- 工具數量與研究品質沒有正相關；先把最小組合跑順。
